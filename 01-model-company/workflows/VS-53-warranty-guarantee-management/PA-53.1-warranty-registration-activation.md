## W2118. POS Warranty Capture at Checkout

| Field | Detail |
|---|---|
| **Trigger** | Customer purchases warranty-eligible product at POS or online |
| **Frequency** | ~420,000 warranty-eligible transactions/month |
| **Volume** | ~420K transactions/month across 200 stores + ecommerce |
| **Owner** | Cashier / POS System |
| **Participants** | Store Manager, IT Integration Lead |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | POS auto-identifies warranty-eligible SKU at scan; prompts cashier; captures transaction date, SKU, serial number, store, loyalty ID; generates the warranty record on the Oracle Install Base item instance (fit-gap D16) | POS System | Cashier | 30–60 sec |
| 2 | Cashier prints warranty card with terms, duration, claim instructions, and registration QR code; customer scans for digital warranty wallet | Cashier | Store Manager | 30 sec |
| 3 | For serial-numbered items: cashier scans or enters serial number; system validates format and links to item+transaction record | Cashier | Cashier | 15–30 sec |
| 4 | System pushes registration to vendor portal (real-time for top 20 vendors; batch daily for others); customer receives SMS/email confirmation | System | IT Integration Lead | Automated |

### System Touchpoints
- POS / warranty capture (links to VS-08 / W5B, POS-013 real-time) — the warranty-eligible identification and capture
- Oracle Install Base + Service Contracts (fit-gap D16; links to VS-13 / W17, W156 CDP) — the warranty record of record
- Vendor portal (links to VS-28 / W593) — the vendor registration push

### Pain Points / Risks
- **Serial-capture-skipped risk**: the cashier skips the serial-number capture (rushed checkout), making a future claim untraceable to the specific unit; mitigated by the mandatory-serial-field for serial-numbered SKUs (the POS won't proceed without it)
- **Vendor-API-failure risk**: the registration push to the vendor portal fails silently, so the vendor doesn't know about the warranty; mitigated by the W2123 data-quality audit catching the push failure

### Automation Opportunity
- Warranty-eligible auto-detected from the item master; serial auto-validated; vendor-push auto-retried on failure

### Controls
- CTL-194 (ensure warranty registration & claim integrity.); CTL-388 (ensure controlled execution — Product Warranty Registration & Activation (PA-53.1).)

### Time Estimate
~90 sec/transaction × ~420,000/month = **~10,500 hours/month Cashier** (absorbed into checkout, ~15 sec incremental over a normal scan).

## W2119. Online Purchase Warranty Registration

| Field | Detail |
|---|---|
| **Trigger** | Ecommerce order with warranty-eligible items fulfilled |
| **Frequency** | ~8,580 warranty registrations/month from ecommerce |
| **Volume** | ~8,580/month |
| **Owner** | Ecommerce System / CRM |
| **Participants** | Ecommerce Ops, Customer |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Ecommerce platform identifies warranty-eligible SKUs; auto-generates registration upon fulfillment confirmation; sends digital warranty certificate via email | System | Ecommerce Ops | Automated |
| 2 | For serial-numbered items: customer prompted to register serial via online form within 14 days; system sends reminders at day 7 and 13 | System | Customer | <1 min |
| 3 | Warranty data pushed to vendor portal; record created on the Install Base instance (fit-gap D16), linked to the customer profile in CRM and visible in mobile app | System | CRM | Automated |

### System Touchpoints
- Ecommerce / warranty (links to VS-10 / W11, W98 order) — the auto-registration on fulfillment
- Oracle Install Base instance on the TCA customer profile (fit-gap D16; links to VS-13 / W17) — the warranty record linked to the customer profile
- Vendor portal (links to VS-28 / W593) — the vendor push

### Pain Points / Risks
- **Serial-registration-non-completion risk**: the customer doesn't register the serial within 14 days (they forget), making the warranty unclaimable; mitigated by the day-7 and day-13 reminders and the 14-day grace extension
- **Fulfillment-trigger-timing risk**: the warranty start-date is the fulfillment confirmation (not the order date), but the customer may expect it from the order date; mitigated by the warranty-start-date clearly stated on the certificate

### Automation Opportunity
- Registration auto-generated on fulfillment; serial-reminders auto-sent; vendor-push auto-retried

### Controls
- CTL-37: warranty validity; CTL-44 (registration integrity); operational: Ecommerce Ops monitoring

### Time Estimate
Automated; Ecommerce Ops ~2 hours/week monitoring = **~100 hours/year**.

## W2120. Bulk Warranty Registration for Trade Accounts

| Field | Detail |
|---|---|
| **Trigger** | Trade/corporate account purchases warranty items in bulk |
| **Frequency** | ~1,050 bulk registrations/month |
| **Volume** | ~1,050/month; avg 5–15 items per invoice |
| **Owner** | Trade Account Manager |
| **Participants** | Head of Trade / Account Management, Customer |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Account Manager creates the project warranty file as linked Install Base instances (fit-gap D16): links all items to project ID, customer account, delivery addresses | Trade Account Mgr | Head of Trade / Account Management | 15–30 min |
| 2 | System auto-registers each item with project-level warranty start date (may differ from invoice date for phased deliveries) | System | Trade Account Mgr | Automated |
| 3 | Account Manager sends consolidated warranty schedule to customer; system schedules expiry alerts at 30 and 90 days before expiry | Trade Account Mgr | Customer | 15 min |

### System Touchpoints
- Oracle Install Base project warranty instances (fit-gap D16; links to VS-13 / W17, VS-11 / W58 corporate account) — the project-level warranty file
- Phased-delivery integration (links to VS-11 / W164 staged delivery, VS-77 material staging) — the per-phase start-date
- Vendor portal (links to VS-28 / W593) — the vendor registration

### Pain Points / Risks
- **Phase-start-date-misalignment risk**: the warranty starts on the invoice date but the item is delivered months later (phased), shortening the effective coverage; mitigated by the project-level start-date tied to delivery confirmation (not invoice date)
- **Bulk-item-individual-tracking risk**: a 100-item bulk warranty is registered as a block, losing individual-item traceability; mitigated by the per-item registration within the project file

### Automation Opportunity
- Project warranty auto-created from the trade invoice; per-item registration auto-generated; expiry-alerts auto-scheduled

### Controls
- CTL-37: warranty validity; CTL-06 (project/customer master); operational: Head of Trade / Account Management sign-off on project warranty files

### Time Estimate
~25 min/bulk × ~1,050/month = **~440 hours/month Trade Account Manager** (distributed across the trade team).

## W2121. Warranty Transfer for Resold Properties

| Field | Detail |
|---|---|
| **Trigger** | Homeowner requests warranty transfer to new property owner |
| **Frequency** | ~50–100 requests/month; peaks in summer renovation |
| **Volume** | ~50–100/month; avg 10–30 items per property |
| **Owner** | Customer Service Rep |
| **Participants** | CSR, Customer Service Director |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | CSR verifies original purchase on the Install Base instance (fit-gap D16); confirms warranty status, remaining coverage; creates transfer record with new owner details | CSR | Customer Service Dir | 10–15 min |
| 2 | System sends transfer confirmation to both parties; updates vendor portal; notes expired items and offers extended warranty renewal | System | CSR | Automated |

### System Touchpoints
- Oracle Install Base instance transfer (fit-gap D16; links to VS-13 / W17) — the original-purchase verification and the transfer record
- Vendor portal (links to VS-28 / W593) — the vendor-notification of the transfer
- Extended warranty (links to VS-53 / W2134) — the renewal offer on expired items

### Pain Points / Risks
- **Fraudulent-transfer risk**: a non-owner requests a transfer to access warranty coverage on items they didn't purchase; mitigated by the original-purchase verification (proof of purchase, identity)
- **Partial-transfer-ambiguity risk**: some items transfer and some don't (the new owner bought some, the old kept some), creating confusion; mitigated by the item-level transfer (not a blanket property transfer)

### Automation Opportunity
- Transfer auto-processed on CSR verification; vendor-notification auto-sent

### Controls
- CTL-37: warranty validity; CTL-153 (consented identity-verification data — links to VS-91 / W53); operational: CS Director sign-off

### Time Estimate
~12 min/transfer × ~75/month = **~15 hours/month CSR**.

## W2122. Warranty Master Data Configuration

| Field | Detail |
|---|---|
| **Trigger** | New product category or warranty terms change |
| **Frequency** | ~5–10 changes/month; quarterly review |
| **Volume** | ~60–120 changes/year across 35,000 SKUs |
| **Owner** | Merchandise Planner |
| **Participants** | Category Manager, VP Merchandising, IT, Legal |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Category Manager defines warranty parameters: type, duration, coverage scope, claim process; Merch Planner configures in ERP item master | Category Mgr | VP Merchandising | 30–60 min |
| 2 | IT configures POS/ecommerce prompts and serial capture rules; Legal reviews for Consumer Act (RA 7394) compliance | IT / Legal | VP Merchandising | 2–3 hours |

### System Touchpoints
- Item/warranty master (links to VS-29 / W252, W296 service-item master) — the warranty parameters per SKU
- POS/ecom config (links to VS-08 / POS, VS-10) — the warranty-prompt and serial-capture rules
- Legal/compliance (links to VS-22 / W22.1 regulatory, VS-88) — the RA 7394 warranty-disclosure review

### Pain Points / Risks
- **RA 7394-non-compliance risk**: the warranty terms don't meet the Consumer Act's minimum (e.g., implied warranty on the sale), creating a consumer-protection exposure; mitigated by the Legal review in step 2
- **Config-vs-master-desync risk**: the warranty master says one duration but the POS prompt says another (config drift); mitigated by the single-source master and the config-refresh

### Automation Opportunity
- Warranty config auto-pushed from the item master to POS/ecom; RA 7394-compliance auto-checked

### Controls
- CTL-51: warranty-master data quality; warranty terms conform to the Consumer Act (RA 7394) — links to VS-22; operational: VP Merchandising sign-off

### Time Estimate
~2 hours/change × ~7/month = **~14 hours/month** Category Manager + IT + Legal.

## W2123. Warranty Data Quality Audit

| Field | Detail |
|---|---|
| **Trigger** | Monthly quality audit schedule |
| **Frequency** | Monthly audit |
| **Volume** | Spot-check ~500 records/month (1%) |
| **Owner** | Data Quality Analyst |
| **Participants** | VP Merchandising |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System generates quality report: registrations without serials, without contacts, duplicates, date anomalies | System | Data Quality Analyst | Automated |
| 2 | Analyst spot-checks 500 records; identifies root causes; escalates training gaps, config errors, or vendor API failures | Data Quality Analyst | VP Merchandising | 4–6 hours |

### System Touchpoints
- Data quality (links to VS-29 / W291 master-data-quality monitoring) — the warranty-record quality checks
- Oracle Install Base + Service Contracts (fit-gap D16; links to VS-13 / W17) — the warranty records audited
- Vendor portal (links to VS-28 / W593) — the vendor-push failure check

### Pain Points / Risks
- **Silent-data-decay risk**: warranty records accumulate quality issues (missing serials, orphaned contacts) without detection, undermining claim validity; mitigated by the monthly audit
- **Root-cause-neglect risk**: quality issues are corrected one-by-one without fixing the systemic cause (a POS config error); mitigated by the root-cause analysis and the system-fix

### Automation Opportunity
- Quality report auto-generated; root-cause auto-categorized

### Controls
- CTL-388 (ensure controlled execution — Product Warranty Registration & Activation (PA-53.1).)
- operational: warranty-data quality; warranty validity — the audit ensures claims are valid; operational: VP Merchandising monthly sign-off

### Time Estimate
~5 hours/month = **~60 hours/year** Data Quality Analyst.

## W2124. Warranty Digital Wallet & Customer Portal

| Field | Detail |
|---|---|
| **Trigger** | Customer accesses warranty portal via app/web |
| **Frequency** | ~10,000–15,000 views/month |
| **Volume** | ~150,000 expected activations in Year 1 |
| **Owner** | Digital Product Manager |
| **Participants** | Customer, Digital PM, CS Agent |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Customer logs in; sees all warranties by status (active, expiring, expired); can view details, claim history, remaining coverage | Customer / System | Digital PM | <1 min/customer |
| 2 | System proactively alerts: warranty expiring in 90 days, product recall notifications, seasonal maintenance reminders | System | Customer | Automated |
| 3 | Customer can initiate claim from portal; upload photos; track status in real-time with push notifications | Customer | CS Agent | 5–10 min |

### System Touchpoints
- App/web portal (links to VS-75 / digital engagement, VS-10 / W98) — the warranty wallet surface
- Oracle Install Base + Service Contracts (fit-gap D16; links to VS-13 / W17, W156 CDP) — the warranty data source
- Push notifications (links to VS-75 app) — the proactive alerts

### Pain Points / Risks
- **Adoption-low risk**: customers don't activate the digital wallet, so the proactive alerts and self-service claim don't reach them; mitigated by the QR-code at checkout (W2118) and the activation incentive
- **Data-privacy risk**: the portal shows purchase history and product details; mitigated by the RA 10173 consent and authentication per VS-91 / W53

### Automation Opportunity
- Wallet auto-populated from the Install Base warranty record (fit-gap D16); alerts auto-sent; claim-initiation auto-routed

### Controls
- CTL-388: data-privacy handling — links to VS-91 / W53; CTL-37 (warranty validity in the portal); operational: Digital PM adoption review

### Time Estimate
~4 hours/week Digital PM = **~200 hours/year**.

## W2125. Warranty Program KPI Monitoring

| Field | Detail |
|---|---|
| **Trigger** | Monthly reporting cycle |
| **Frequency** | Monthly dashboard; weekly metrics |
| **Volume** | Full chain: 200 stores + ecommerce + trade |
| **Owner** | VP Merchandising |
| **Participants** | Category Managers, CS Director |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System generates dashboard: active warranties by category, registration rate, claim rate, avg resolution time, warranty cost %, extended warranty attach rate | System | VP Merchandising | Automated |
| 2 | Category Managers review high claim rate categories (>5%); CS Director reviews claim satisfaction (target ≥80%); VP reviews warranty P&L | Various | VP Merchandising | 2–3 hours |

### System Touchpoints
- Analytics/BI (links to VS-27 / W113) — the warranty-program dashboard
- Install Base/Service-Contracts warranty dataset (fit-gap D16; links to VS-13 / W17, VS-53 / W2118–W2133) — the warranty dataset
- P&L (links to VS-17 / W9, VS-158 / W85) — the warranty-cost view

### Pain Points / Risks
- **Claim-rate-spike-blindness risk**: a category's claim rate spikes (a quality issue) but isn't caught until month-end; mitigated by the weekly operational metrics alongside the monthly dashboard
- **Cost-vs-customer-experience-imbalance risk**: pushing the warranty-cost % down (denying more claims) erodes customer satisfaction; mitigated by the satisfaction KPI alongside the cost KPI

### Automation Opportunity
- Dashboard auto-refreshed; high-claim-rate auto-flagged; weekly operational metrics auto-distributed

### Controls
- CTL-388 (ensure controlled execution — Product Warranty Registration & Activation (PA-53.1).)
- CTL-388: warranty-program register accuracy; operational: VP Merchandising monthly sign-off; Category Manager review on >5% claim rate

### Time Estimate
~2.5 hours/month = **~30 hours/year** VP Merchandising + Category Managers.
