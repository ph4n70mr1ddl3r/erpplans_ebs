## W1819. Project Cost Capture & Allocation

| Field | Detail |
|---|---|
| **Trigger** | Invoice received, goods received, or labor cost incurred for capex project |
| **Frequency** | ~200–500 cost entries/month across active projects |
| **Volume** | ~2,500–6,000 cost entries/year |
| **Owner** | Project Accountant |
| **Participants** | Project Accountant, Project Manager, AP, Department Head |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Cost capture methods: (a) **vendor invoices** linked to PO: AP matches invoice to PO and GR; cost auto-allocated to project, (b) **internal labor**: project time tracked by timesheet; labor cost allocated from payroll to project (capitalized if directly attributable), (c) **internal purchases**: requisitions for project materials charged to project cost center, (d) **overhead allocation**: project management costs, insurance, permits allocated based on policy | System / Project Accountant | Accounting Manager | Continuous |
| 2 | System auto-allocates costs to project based on PO reference: (a) each PO references a capex project number, (b) invoice matching against PO auto-charges cost to project CIP account, (c) costs categorized: materials, labor, equipment, services, permits, contingency, (d) running total per project updated in real-time | System | Project Accountant | Automated |
| 3 | Project Accountant reviews unallocated costs weekly: (a) invoices received without project reference — identify correct project and allocate, (b) costs charged to wrong project — reclassify, (c) costs charged to operating expense that should be capitalized — journal entry to reclassify to CIP | Project Accountant | Accounting Manager | 2–4 hours/week |
| 4 | Monthly: Project Accountant reconciles project CIP accounts to project budget and actual costs; unresolved items escalated to Project Manager | Project Accountant | Accounting Manager | 1–2 days/month |


### System Touchpoints
- Cost capture methods — vendor invoices matched to PO/GR, labor journal entries (step 1)
- Auto-allocation to project via PO reference (step 2)
- Weekly review of unallocated costs (step 3)
- Monthly CIP-to-budget reconciliation (step 4)

### Pain Points / Risks
- **Orphan-cost risk**: invoices without project reference sit unallocated, understating project cost; mitigated by weekly unallocated review (step 3)
- **Wrong-project allocation risk**: costs booked to the wrong CPX number; mitigated by PO-reference auto-allocation with monthly reconciliation (steps 2, 4)

### Automation Opportunity
- System auto-capture of "Cost capture methods" (replaces manual Step 1).
- System auto-review of "reviews unallocated costs weekly" (replaces manual Step 3).

### Controls
- CTL-362 (ensure controlled execution — Project Cost Tracking & Capitalization (PA-40.2).)
- operational: Project Accountant review and approval gate; periodic reconciliation against source documents

### Time Estimate
Weekly unallocated-cost review 2–4 hours ≈ 104–208 hours/year; monthly project CIP-to-budget reconciliation 1–2 days ≈ 12–24 days/year across ~200–500 cost entries/month (invoice-to-PO matching and cost allocation automated).

## W1820. Construction Progress Payment & Contractor Billing

| Field | Detail |
|---|---|
| **Trigger** | Contractor submits progress billing (typically monthly) |
| **Frequency** | ~4–8 progress billings per construction project |
| **Volume** | ~40–120 progress billings/year (10–15 new stores × 4–8 billings) |
| **Owner** | COO |
| **Participants** | COO, Project Engineer, Project Accountant, Contractor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Contractor submits progress billing with: (a) % completion claimed, (b) work completed this period (description and quantities), (c) materials delivered and installed, (d) billing amount = total contract × % completion − previous billings, (e) supporting documentation: photos, delivery receipts, inspection reports | Contractor | COO | Monthly per project |
| 2 | Project Engineer verifies progress claim: (a) site inspection: confirm claimed work is actually completed, (b) quantity verification: measure installed items vs. claimed quantities, (c) quality check: installed work meets specifications, (d) recommends approved billing % (may be less than contractor's claim if work incomplete or deficient) | Project Engineer | COO | 1–2 days/billing |
| 3 | COO approves progress payment: (a) approved amount = contract × approved % − previous payments − retention (typically 10% retention until project completion and final acceptance), (b) Project Accountant records: debit CIP, credit AP (contractor), (c) retention withheld: recorded as AP retention liability | COO / Project Accountant | CFO (for amounts > PHP 5M) | 1 day |
| 4 | AP processes payment per standard payment cycle; retention released upon: (a) project completion certificate signed, (b) punch list items resolved (typically 3–6 months post-completion), (c) CFO approves retention release | AP / COO | CFO | Per retention schedule |

### System Touchpoints
- Progress billing intake — % completion claimed, quantities, supporting docs (step 1)
- Site verification — inspection and quantity verification of claimed work (step 2)
- Payment computation — contract × approved % − prior payments − retention (step 3)
- Retention release on completion certificate and punch-list clearance (step 4)

### Pain Points / Risks
- **Overpayment risk**: Paying for work not actually completed; rigorous site inspection is critical; mitigated by the COO review and approval gate
- **Retention disputes**: Contractors may dispute retention amount or delay resolution of punch list items to get retention released
- **Cost escalation**: Philippine construction costs can escalate rapidly (material prices, labor rates); fixed-price contracts recommended

### Automation Opportunity
- System auto-document of "Contractor submits progress billing with" (replaces manual Step 1).
- System auto-validate of "Project Engineer verifies progress claim" (replaces manual Step 2).
- System auto-record of "COO approves progress payment" (replaces manual Step 3).

### Controls
- CTL-362 (ensure controlled execution — Project Cost Tracking & Capitalization (PA-40.2).)
- operational: COO review and approval gate

### Time Estimate
~1 day of verification-approval effort per progress billing (site-claim verification over 1–2 days elapsed + VP approval 1 day; retention per schedule) × ~40–120 progress billings/year ≈ 40–120 days/year.

## W1821. Project Material & Equipment Cost Tracking

| Field | Detail |
|---|---|
| **Trigger** | Materials or equipment received for capex project |
| **Frequency** | ~50–100 material receipts/month across active projects |
| **Volume** | ~600–1,200 receipts/year |
| **Owner** | Project Accountant |
| **Participants** | Project Accountant, Receiving Clerk, Project Manager |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Materials and equipment received at project site or DC: (a) receiving clerk processes GR against PO, (b) PO references capex project number, (c) system auto-charges cost to project CIP, (d) materials stored at project site or DC until needed | Receiving Clerk | Project Manager | Per receipt |
| 2 | Special cost tracking for new store projects: (a) POS terminals (3 per store): tracked individually as future fixed assets, (b) shelving and racking: tracked as bulk material cost → allocated to component assets at turnover, (c) signage: tracked per store, (d) generator: tracked as individual asset, (e) paint, cement, electrical supplies: bulk materials tracked as construction cost → component of leasehold improvement asset | Project Accountant | Accounting Manager | Continuous |
| 3 | Waste and surplus tracking: (a) unused materials at project completion: returned to vendor for credit or transferred to next project, (b) wasted materials (damage, spoilage): documented and written off to project cost, (c) surplus inventory at store opening: transferred to store operating inventory (reclass from CIP to inventory asset) | Project Manager / Project Accountant | COO | At project completion |


### System Touchpoints
- Materials GR against project-referenced POs (step 1)
- Special asset tracking — POS terminals, fixtures as future fixed-asset components (step 2)
- Surplus material return/transfer at completion (step 3)

### Pain Points / Risks
- **Material-diversion risk**: project materials used elsewhere or pilfered; mitigated by GR-to-project linkage and completion surplus tracking (steps 1, 3)
- **Lost-component risk**: individually valuable items (terminals) never become assets at turnover; mitigated by item-level tracking feeding W1829 (step 2)

### Automation Opportunity
- System auto-track of "tracking for new store projects" (replaces manual Step 2).
- System auto-document of "documented and written off to project cost" (replaces manual Step 3).

### Controls
- CTL-210 (ensure capex authorization & commitment control.)
- operational: standard operating procedures; system-enforced validation rules

### Time Estimate
Project material receipting ~15–30 min/receipt (GR processing + special cost-tagging for store assets) × ~50–100 receipts/month ≈ 150–600 hours/year; waste/surplus disposition at project completion.

## W1822. Professional Service & Consulting Fee Tracking

| Field | Detail |
|---|---|
| **Trigger** | Consulting or professional service invoice received for capex project |
| **Frequency** | ~50–100 invoices/year |
| **Volume** | Architecture, engineering, project management, IT consulting fees |
| **Owner** | Project Accountant |
| **Participants** | Project Accountant, COO, CIO, External Service Providers |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Professional services in capex projects: (a) architectural and engineering design (typically 3–5% of construction cost), (b) project management (in-house or external PM), (c) IT consulting for system implementations, (d) geotechnical survey and soil testing, (e) environmental impact assessment (if required by DENR), (f) legal fees for permits and contracts, (g) audit fees for project cost verification | Project Manager | COO / CIO | Continuous |
| 2 | Professional service invoices reviewed and approved: (a) verify services were actually performed (timesheets, deliverables), (b) verify billing is per contract terms (hourly rate, fixed fee, or % complete), (c) approve and process payment, (d) cost charged to project CIP | Project Manager / Project Accountant | Department Head | 1–2 days/invoice |
| 3 | Capitalization of professional fees: (a) directly attributable fees capitalized as part of project cost (architect, engineer, PM), (b) general administrative overhead not capitalized (HQ staff time not specifically devoted to project), (c) financing costs: borrowing costs directly attributable to qualifying asset capitalized per PFRS per W1824 | Project Accountant | Accounting Manager | At each invoice |


### System Touchpoints
- Professional fee categories — design (3–5% of construction), PM, supervision, permits (step 1)
- Invoice verification — services performed per timesheets/deliverables (step 2)
- Capitalization vs. expense treatment of fees (step 3)

### Pain Points / Risks
- **Ghost-service risk**: invoices approved for work never performed; mitigated by deliverable/timesheet verification (step 2)
- **Mis-capitalization risk**: non-attributable fees capitalized into CIP; mitigated by capitalization criteria per fee type (step 3)

### Automation Opportunity
- System auto-test of "Professional services in capex projects" (replaces manual Step 1).
- System auto-review of "reviewed and approved" (replaces manual Step 2).

### Controls
- CTL-362 (ensure controlled execution — Project Cost Tracking & Capitalization (PA-40.2).)
- operational: Project Accountant review and approval gate

### Time Estimate
~0.5–1 day per professional-services invoice (delivery verification + capitalization treatment; complex engagements 1–2 days elapsed) × ~50–100 invoices/year ≈ 25–100 days/year.

## W1823. Project Cost Capitalization vs. Expense Determination

| Field | Detail |
|---|---|
| **Trigger** | Cost incurred for capex-related item; determination needed whether to capitalize or expense |
| **Frequency** | Every cost transaction (~200–500/month) |
| **Volume** | ~2,500–6,000 determinations/year |
| **Owner** | Project Accountant |
| **Participants** | Project Accountant, Accounting Manager, CFO |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Capitalization policy per PFRS/IAS 16: **Capitalize** (add to CIP → future fixed asset): (a) purchase price of asset (including non-recoverable taxes, delivery, installation), (b) costs directly attributable to bringing asset to working condition (site preparation, initial delivery, installation, testing), (c) professional fees directly attributable (architect, engineer, project management), (d) borrowing costs directly attributable to qualifying asset per PFRS 23 (W1824), (e) demolition/dismantling costs of old assets (if replacement project), (f) initial operating losses: NOT capitalized (expensed) | Project Accountant | Accounting Manager | Per transaction |
| 2 | **Expense** (charge to P&L in period incurred): (a) costs below capitalization threshold (PHP 20K), (b) training costs for staff to operate new asset, (c) general administrative overhead not directly attributable, (d) operating losses in initial period (new store ramp-up losses), (e) marketing and promotional costs (grand opening), (f) relocation costs, (g) maintenance costs (vs. improvement — distinction per W1695) | Project Accountant | Accounting Manager | Per transaction |
| 3 | Gray area determinations escalated to Accounting Manager: (a) software customization vs. license (customization = capitalize; license = intangible asset), (b) repair during construction (capitalize if part of project scope), (c) change order due to design error (capitalize — part of project cost), (d) insurance claim recovery during construction (reduce project cost) | Project Accountant | Accounting Manager | As needed |
| 4 | Monthly: Accounting Manager reviews all capitalized costs for appropriateness; any items incorrectly capitalized are reclassified to expense; policy guidance updated for common errors | Accounting Manager | CFO | 1 day/month |


### System Touchpoints
- Capitalization policy per PFRS/IAS 16 — capitalize purchase price, delivery, installation, directly attributable costs (step 1)
- Expense rules — below PHP 20K threshold, training, routine repairs (step 2)
- Gray-area escalation and monthly appropriateness review with reclassification (steps 3–4)

### Pain Points / Risks
- **Aggressive-capitalization risk**: operating costs parked in CIP to flatter P&L; mitigated by monthly review and reclassification (step 4)
- **Inconsistent-treatment risk**: similar costs treated differently across projects; mitigated by the documented policy with escalation for gray areas (steps 1, 3)

### Automation Opportunity
- System auto-test of "Capitalization policy per PFRS/IAS 16" (replaces manual Step 1).
- System auto-count of "Gray area determinations escalated to Accounting Manager" (replaces manual Step 3).
- System auto-review of "reviews all capitalized costs for appropriateness" (replaces manual Step 4).

### Controls
- CTL-362 (ensure controlled execution — Project Cost Tracking & Capitalization (PA-40.2).)
- operational: Project Accountant review and approval gate

### Time Estimate
Per-transaction capitalization largely policy-rules-driven across ~200–500 monthly cost transactions; gray-area escalations to the Accounting Manager as needed; monthly capitalized-cost appropriateness review 1 day ≈ 12 days/year.

## W1824. Capitalized Interest Calculation & Recording

| Field | Detail |
|---|---|
| **Trigger** | Active capex project with qualifying asset financed by borrowing; monthly close |
| **Frequency** | Monthly calculation during construction period |
| **Volume** | Only for projects financed by specific borrowing (typically large new stores or DC projects > PHP 50M) |
| **Owner** | Treasury |
| **Participants** | Treasury, Project Accountant, Accounting Manager |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Per PFRS 23 (Borrowing Costs): capitalize borrowing costs directly attributable to acquisition, construction, or production of a qualifying asset: (a) qualifying asset: asset that takes substantial time to get ready for intended use (new store construction, DC expansion qualify), (b) capitalization period: from when expenditures and borrowing costs are incurred until asset is substantially ready for use, (c) capitalization ceases when substantially all activities necessary to prepare the asset are complete | Treasury | Accounting Manager | Monthly |
| 2 | Calculation: (a) for specific borrowing: actual interest incurred on the loan financing the project, (b) for general borrowing: weighted average cost of outstanding borrowings × cumulative expenditures on the asset, (c) capitalization amount cannot exceed actual interest incurred, (d) calculation performed monthly | Treasury | CFO | 1–2 hours/project/month |
| 3 | Journal entry: (a) debit: CIP (capitalized interest), (b) credit: interest expense (reduces P&L interest expense), (c) capitalized interest becomes part of the asset's cost and is depreciated over its useful life | Treasury / Project Accountant | Accounting Manager | Monthly |
| 4 | Capitalization ceases when store opens (substantially ready for use); any interest after opening is expensed | Treasury | Accounting Manager | At project completion |


### System Touchpoints
- PFRS 23 borrowing-cost capitalization for qualifying assets (step 1)
- Calculation — specific borrowing interest; general borrowing weighted-average rate (step 2)
- Journal entry — debit CIP, credit interest expense; cessation at readiness (steps 3–4)

### Pain Points / Risks
- **Over-capitalization risk**: interest capitalized beyond the construction period; mitigated by cessation when substantially ready for use (step 4)
- **Rate-application error**: general-borrowing pool rates misapplied; mitigated by the documented weighted-average methodology (step 2)

### Automation Opportunity
- System auto-generate of "prepare the asset are complete" (replaces manual Step 1).

### Controls
- CTL-362 (ensure controlled execution — Project Cost Tracking & Capitalization (PA-40.2).)
- operational: standard operating procedures; system-enforced validation rules

### Time Estimate
Capitalized-borrowing-cost calculation 1–2 hours/project/month × the specifically-financed large projects (PHP 50M+) ≈ 40–200 hours/year; monthly journal posting; capitalization ceases when the asset is substantially ready for use.

## W1825. Project Budget vs. Actual Variance Reporting

| Field | Detail |
|---|---|
| **Trigger** | Monthly management reporting |
| **Frequency** | Monthly |
| **Volume** | ~30–50 active projects |
| **Owner** | FP&A |
| **Participants** | FP&A, Project Manager, COO, CIO, CFO |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System generates project-level budget vs. actual report: (a) approved budget by cost category, (b) committed costs (POs issued), (c) incurred costs (invoices processed), (d) paid costs (payments made), (e) remaining budget, (f) forecast to complete (Project Manager estimate), (g) forecast total cost = incurred + forecast to complete, (h) variance = forecast total − approved budget | System | FP&A | Automated |
| 2 | FP&A analyzes variances: (a) favorable (< budget): identify if scope reduction, value engineering, or under-delivery, (b) unfavorable (> budget): identify root cause (scope increase, cost escalation, design error, contractor delay), (c) trend: is variance increasing or stable? (d) contingency utilization: how much contingency remains? | FP&A | CFO | 1–2 days/month |
| 3 | Project-level variance actions: (a) < 5% over budget: Project Manager manages within contingency, (b) 5–15% over budget: requires change order per W1815 and VP approval, (c) > 15% over budget: requires CFO/CEO review and may require additional board approval, (d) systemic overrun pattern (multiple projects over budget): triggers process review | FP&A / CFO | CEO | Monthly |


### System Touchpoints
- Monthly project budget-vs-actual report — committed, incurred, remaining (step 1)
- Variance analysis — favorable and unfavorable with root cause (step 2)
- Tiered variance actions — < 5% within contingency; 5–15% CFO; > 15% Board (step 3)

### Pain Points / Risks
- **Favorable-variance-complacency risk**: underspend signals scope under-delivery, not savings; mitigated by analyzing favorable variances too (step 2)
- **Late-escalation risk**: overruns surface after money is spent; mitigated by tiered action thresholds at each monthly review (step 3)

### Automation Opportunity
- System auto-generate of "generates project-level budget vs." (replaces manual Step 1).
- System auto-analyze of "FP&A analyzes variances" (replaces manual Step 2).
- System auto-review of "review and may require additional board approval" (replaces manual Step 3).

### Controls
- CTL-362 (ensure controlled execution — Project Cost Tracking & Capitalization (PA-40.2).)
- operational: FP&A review and approval gate

### Time Estimate
Monthly project budget-vs-actual analysis 1–2 days ≈ 12–24 days/year across ~30–50 active projects (report generation automated); variance actions per the 5%/15% thresholds.

## W1826. Multi-Entity Project Cost Allocation

| Field | Detail |
|---|---|
| **Trigger** | Capex project benefits multiple entities (e.g., IT system used by all 5 entities) |
| **Frequency** | ~10–20 multi-entity allocations/year |
| **Volume** | Primarily IT and shared service projects |
| **Owner** | FP&A |
| **Participants** | FP&A, CFO, CIO |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Multi-entity project examples: (a) ERP system upgrade: benefits all 5 entities — allocated by headcount or revenue, (b) new DC (BuildRight Logistics Inc.): primarily benefits Depot Inc. (stores it serves) — allocation by store volume, (c) corporate HQ renovation: allocated to Holdings Inc., (d) ecommerce platform: primarily Digital Commerce Inc. and Depot Inc. — allocated by order volume | FP&A | CFO | Per project |
| 2 | Allocation methodology: (a) headcount-based: total headcount per entity (Depot: 5,800 store staff + 600 DC staff; Digital Commerce: ~30; Property: ~15; Holdings/HQ: ~525 active per profile §3.3/§11.1 (the TO's 532-role design retains the disabled—prepared Trade department — 2026-09-23 (x); promoted 2026-09-14; gap-filled 2026-09-18) — total ~6,925), (b) revenue-based: revenue per entity, (c) usage-based: transaction volume per entity, (d) methodology documented and approved by CFO; consistently applied | FP&A | CFO | 1 day |
| 3 | System posts intercompany allocations: (a) primary entity incurs cost → allocates to other entities via intercompany journal entries, (b) each entity records its share as capex in its own CIP, (c) intercompany receivable/payable created for the allocation amount | System / Project Accountant | Accounting Manager | Monthly or at project completion |
| 4 | Transfer pricing documentation: for intercompany cost allocations, ensure arm's-length basis per BIR transfer pricing rules per W1731 | FP&A / Tax Accountant | CFO | At allocation |


### System Touchpoints
- Multi-entity allocation methodology — headcount or revenue basis (steps 1–2)
- Intercompany allocation postings between entities (step 3)
- Transfer pricing documentation per BIR rules (step 4)

### Pain Points / Risks
- **Arbitrary-allocation risk**: allocation bases challenged by BIR as non-arm's-length; mitigated by documented methodology and TP documentation (steps 2, 4)
- **Entity-P&L distortion risk**: the primary entity carries all multi-entity cost until allocation; mitigated by systematic IC posting (step 3)

### Automation Opportunity
- System auto-log of "Multi-entity project examples: (a) ERP system upgrade: benefits" (replaces manual Step 1).
- System auto-document of "documented and approved by CFO" (replaces manual Step 2).
- System auto-record of "records its share as capex in its own CIP" (replaces manual Step 3).

### Controls
- CTL-362 (ensure controlled execution — Project Cost Tracking & Capitalization (PA-40.2).)
- operational: FP&A review and approval gate

### Time Estimate
Per multi-entity project ~1–2 days (allocation methodology + intercompany postings with transfer-pricing documentation) × ~10–20 allocations/year ≈ 10–40 days/year.
