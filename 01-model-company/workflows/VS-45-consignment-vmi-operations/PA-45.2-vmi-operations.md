## W1934. VMI Agreement Setup & Parameter Configuration

| Field | Detail |
|---|---|
| **Trigger** | New VMI vendor onboarding; annual VMI agreement renewal |
| **Frequency** | ~2–3 new VMI vendors/year; 12 vendors reviewed annually |
| **Volume** | ~300 VMI SKUs across 12 key vendors |
| **Owner** | VP Supply Chain |
| **Participants** | VP Supply Chain, Category Manager, VP Merchandising, Vendor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | VP Supply Chain negotiates VMI agreement with vendor: (a) scope: which SKUs are VMI-managed, which locations (DCs, stores, or both), (b) inventory parameters: minimum stock level, maximum stock level, reorder point, reorder quantity per SKU per location, (c) data sharing: BuildRight provides daily stock levels, sales data, forecast; vendor manages replenishment decisions, (d) service level: target fill rate ≥ 97%, lead time commitment, (e) ownership: VMI stock is BuildRight-owned (unlike consignment), vendor manages replenishment but BuildRight owns inventory upon receipt, (f) settlement: standard PO-based, 3-way match per W7 | VP Supply Chain / Category Manager | VP Merchandising | Per negotiation |
| 2 | System configuration: (a) VMI flag set on applicable SKUs in item master, (b) VMI parameters per SKU per location: min/max/ROP/ROQ, (c) data sharing schedule: daily automated stock/sales feed to vendor, (d) auto-replenishment: vendor-generated replenishment suggestions auto-create PO upon BuildRight approval or auto-approve per threshold, (e) auto-confirmation: GR auto-confirmed against VMI ASN within tolerance | System / IT | VP Supply Chain | 2–4 hours/vendor |
| 3 | Test cycle: (a) run 4-week VMI pilot with vendor for 1 DC, (b) measure: fill rate, stockout frequency, overstock instances, GR accuracy, (c) adjust parameters based on pilot results, (d) roll out to all applicable locations | VP Supply Chain | VP Merchandising | 4 weeks |

### System Touchpoints
- VMI parameter configuration in procurement/inventory module (W1934.2)
- Automated data sharing API setup (W1934.2)
- Integration with W36 (vendor onboarding) for vendor setup

### Pain Points / Risks
- **Parameter accuracy**: Incorrect min/max levels lead to either stockouts (too low) or excess inventory (too high); requires demand history analysis for accurate parameter setting
- **Vendor capability**: Not all vendors have EDI/API capability for VMI; smaller vendors may need manual data sharing (email spreadsheets)


### Automation Opportunity
- System auto-flag of "settlement: standard PO-based, 3-way match per W7" (replaces manual Step 1).
- System auto-generate of "auto-create PO upon BuildRight approval or auto-approve per threshold" (replaces manual Step 2).

### Controls
- CTL-377 (ensure controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2).)
- operational: VP Supply Chain review and approval gate

### Time Estimate
- ~4–6 weeks per vendor setup (1–2 weeks negotiation/configuration + the 4-week pilot test cycle)

## W1935. VMI Data Sharing & Demand Signal Transmission

| Field | Detail |
|---|---|
| **Trigger** | Daily automated schedule |
| **Frequency** | Daily |
| **Volume** | ~300 VMI SKUs × ~204 locations (4 DCs + 200 stores) = ~61,200 data points/day |
| **Owner** | System |
| **Participants** | System, VP Supply Chain, Vendor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System compiles daily VMI data package per vendor: (a) current stock level per SKU per location, (b) daily sales (units) per SKU per location, (c) in-transit stock (VMI POs not yet received), (d) pending returns, (e) forecast data (if available from W31 demand forecast), (f) promotional calendar impact (upcoming promos affecting VMI SKUs) | System | VP Supply Chain | Automated |
| 2 | System transmits data to vendor: (a) preferred: API/EDI transmission directly to vendor's VMI system, (b) fallback: automated email with CSV/Excel attachment, (c) transmission log maintained for audit trail | System | — | Automated |
| 3 | VP Supply Chain monitors data transmission: (a) daily check: did all 12 vendors receive data successfully?, (b) failed transmission: retry within 2 hours, (c) vendor feedback: any data quality issues reported?, (d) monthly: review data accuracy (do vendor's stock numbers match BuildRight's?) | VP Supply Chain | — | 15–30 min/day |

### System Touchpoints
- Automated VMI data extraction and packaging (W1935.1)
- API/EDI transmission with logging (W1935.2)
- Integration with W31 (demand forecasting) for forecast data

### Pain Points / Risks
- **Data latency**: If POS inventory deduction is delayed (per POS-013, < 30 sec), VMI data may be slightly stale; acceptable for daily batch but not for real-time VMI
- **Data volume**: 61,200 data points/day for 12 vendors is manageable but requires automated processing


### Automation Opportunity
- System auto-review of "review data accuracy" (replaces manual Step 3).

### Controls
- CTL-377 (ensure controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2).)
- operational: System review and approval gate

### Time Estimate
- Automated transmission; 15–30 min/day monitoring

## W1936. VMI Automated Replenishment & ASN Processing

| Field | Detail |
|---|---|
| **Trigger** | Vendor generates replenishment suggestion based on VMI data |
| **Frequency** | ~200–300 VMI replenishment orders/month |
| **Volume** | ~300 VMI SKUs across 12 vendors |
| **Owner** | VP Supply Chain |
| **Participants** | VP Supply Chain, Buyer, Vendor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Vendor reviews VMI data and generates replenishment order: (a) vendor's VMI system calculates replenishment needs based on min/max parameters and recent sales, (b) vendor creates ASN (Advance Shipping Notice) with: SKU, qty, ship date, estimated arrival, (c) ASN transmitted to BuildRight system via API/EDI | Vendor | VP Supply Chain | Vendor-driven |
| 2 | BuildRight system processes ASN: (a) auto-create PO from ASN (within VMI agreement parameters), (b) validate: (i) total PO value within VMI agreement spending limit, (ii) SKU qty within min/max parameters, (iii) delivery schedule aligns with DC/store receiving capacity, (c) if within tolerance: auto-approve PO, (d) if outside tolerance: route to Buyer for manual review | System / Buyer | VP Supply Chain | Automated + exception handling |
| 3 | Buyer reviews exceptions: (a) vendor suggests qty above max level: reject or approve with reason (e.g., upcoming promo), (b) vendor suggests SKUs not in VMI agreement: reject, (c) vendor suggests delivery to non-VMI location: reject, (d) document exception resolution | Buyer | VP Supply Chain | 15–30 min/exception |

### System Touchpoints
- ASN-to-PO auto-creation (W1936.2)
- Tolerance-based auto-approval (W1936.2)
- Integration with W2A (auto-replenishment) for PO creation

### Pain Points / Risks
- **Overstocking risk**: Vendor has incentive to push more stock (ensures shelf presence); min/max parameters and spending caps prevent excess; mitigated by CTL-377 (controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2))
- **Auto-approval risk**: If parameters are set too loosely, system may auto-approve excessive replenishment; requires periodic parameter review; mitigated by CTL-377 (controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2))


### Automation Opportunity
- System auto-review of "reviews VMI data and generates replenishment order" (replaces manual Step 1).
- System auto-validate of "BuildRight system processes ASN" (replaces manual Step 2).
- System auto-document of "document exception resolution" (replaces manual Step 3).

### Controls
- CTL-377 (ensure controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2).)
- operational: periodic VMI parameter review with min/max and spending caps

### Time Estimate
- Automated for standard replenishment; 15–30 min per exception

## W1937. VMI Goods Receipt & Auto-Confirmation

| Field | Detail |
|---|---|
| **Trigger** | VMI delivery arrives at DC or store |
| **Frequency** | ~200–300 VMI receipts/month |
| **Volume** | ~300 VMI SKUs |
| **Owner** | Receiving Clerk |
| **Participants** | Receiving Clerk, System, Vendor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Receiving Clerk processes VMI delivery: (a) scan ASN barcode or enter PO number, (b) verify quantities against ASN, (c) standard goods receipt process: scan items, check condition, (d) system posts GR: (i) inventory increases at WAC (BuildRight-owned, unlike consignment), (ii) GR/IR created for 3-way match, (iii) AP liability created | Receiving Clerk | Department Supervisor | 15–30 min/receipt |
| 2 | Auto-confirmation: (a) if GR qty within ASN tolerance (typically ±2%), system auto-confirms receipt to vendor via API, (b) vendor's VMI system updates stock position automatically, (c) if GR qty outside tolerance: manual discrepancy resolution with vendor per W244 | System | — | Automated |
| 3 | Invoice matching: (a) vendor invoice received, (b) system performs 3-way match: PO → GR → Invoice, (c) standard AP processing per W7 | System / AP Clerk | AP Manager | Per standard AP cycle |

### System Touchpoints
- VMI GR with auto-confirmation (W1937.2)
- 3-way match for VMI POs (W1937.3)
- Integration with W3 (DC receiving) and W18 (DSD receiving)

### Pain Points / Risks
- **ASN accuracy**: If vendor's ASN quantities don't match actual delivery, auto-confirmation creates reconciliation issues; enforce ASN accuracy KPI in vendor scorecard


### Automation Opportunity
- System auto-capture of "enter PO number" (replaces manual Step 1).
- System auto-update of "updates stock position automatically" (replaces manual Step 2).
- System auto-match of "matching" (replaces manual Step 3).

### Controls
- CTL-174 (ensure consignment & VMI settlement integrity.)
- operational: standard operating procedures; system-enforced validation rules

### Time Estimate
- 15–30 min per receipt; auto-confirmation is automated

## W1938. VMI Stock Level Monitoring & Exception Management

| Field | Detail |
|---|---|
| **Trigger** | Daily VMI stock level monitoring |
| **Frequency** | Daily monitoring; weekly review |
| **Volume** | ~300 VMI SKUs × ~205 locations |
| **Owner** | VP Supply Chain |
| **Participants** | VP Supply Chain, Buyer, Vendor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | System monitors VMI stock levels daily: (a) flag SKUs below minimum level (stockout risk), (b) flag SKUs above maximum level (overstock risk), (c) flag SKUs at zero stock (immediate action needed), (d) flag SKUs with consistent above-max pattern (parameter adjustment needed) | System | VP Supply Chain | Automated |
| 2 | VP Supply Chain reviews exceptions: (a) below-min: did vendor replenish? If not, escalate to vendor with SLA breach notice, (b) above-max: did vendor over-ship? Request return or adjust future orders, (c) zero stock: emergency replenishment — expedite from vendor or transfer from another location per W22 | VP Supply Chain | VP Merchandising | 30–60 min/day |
| 3 | Weekly: VP Supply Chain conducts VMI exception review with Category Manager: (a) top 10 stockout SKUs by lost sales estimate, (b) top 10 overstock SKUs by excess value, (c) vendor response time to replenishment triggers, (d) adjust VMI parameters if systemic issues identified | VP Supply Chain / Category Manager | VP Merchandising | 1 hour/week |

### System Touchpoints
- VMI exception monitoring dashboard (W23)
- Automated alerts to vendor and BuildRight supply chain team (W23)
- Integration with W250 (supply chain control tower) for visibility

### Pain Points / Risks
- **Stockout responsibility**: When VMI SKUs stock out, BuildRight may blame vendor but vendor may cite inaccurate demand signals; clear SLA and root cause assignment needed


### Automation Opportunity
- System auto-monitor of "monitors VMI stock levels daily" (replaces manual Step 1).
- System auto-review of "VP Supply Chain reviews exceptions" (replaces manual Step 2).
- System auto-issue of "issues identified" (replaces manual Step 3).

### Controls
- CTL-377 (ensure controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2).)
- operational: VP Supply Chain review and approval gate

### Time Estimate

## W1939. VMI New Product Introduction & Phase-Out

| Field | Detail |
|---|---|
| **Trigger** | New product launch; product phase-out decision |
| **Frequency** | ~20–30 VMI SKU changes/year |
| **Volume** | ~300 VMI SKUs managed |
| **Owner** | Category Manager |
| **Participants** | Category Manager, VP Supply Chain, Vendor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | New VMI product introduction: (a) Category Manager adds new SKU to VMI agreement, (b) VP Supply Chain configures VMI parameters (min/max/ROP/ROQ) based on similar product demand history, (c) initial stock: vendor ships initial fill within 2 weeks of SKU activation, (d) monitor closely for first 4 weeks: compare actual demand to parameter assumptions | Category Manager / VP Supply Chain | VP Merchandising | 1–2 days/SKU |
| 2 | VMI product phase-out: (a) Category Manager flags SKU for phase-out in VMI agreement, (b) vendor stops replenishment, (c) remaining VMI stock sold through normally (or returned to vendor per agreement), (d) once stock reaches zero: remove from VMI parameters, (e) if significant remaining stock: negotiate vendor buyback or markdown support | Category Manager / VP Supply Chain | VP Merchandising | 1–2 weeks/phase-out |

- SKU phase-out flag in VMI module (W1939.2)
- Integration with W315 (product lifecycle status governance)

### Pain Points / Risks
- **Initial parameter guessing**: New products have no demand history; parameters based on similar items may be inaccurate; expect 2–3 parameter adjustments in first 2 months


### Automation Opportunity
- System auto-monitor of "monitor closely for first 4 weeks" (replaces manual Step 1).
- System auto-flag of "flags SKU for phase-out in VMI agreement" (replaces manual Step 2).

### Controls
- CTL-377 (ensure controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2).)

## W1940. VMI Promotional Stock Planning & Allocation

| Field | Detail |
|---|---|
| **Trigger** | Promotional calendar event involving VMI SKUs |
| **Frequency** | ~6 major promos/year; ~2–3 VMI SKUs per promo |
| **Volume** | ~12–18 VMI promo events/year |
| **Owner** | Category Manager |
| **Participants** | Category Manager, VP Supply Chain, Pricing Analyst, Vendor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Category Manager plans VMI promotional stock: (a) identify VMI SKUs in upcoming promo per W13, (b) estimate incremental demand: historical promo lift × base demand, (c) communicate to vendor: (i) promo dates, (ii) expected volume increase, (iii) required pre-positioning: extra stock in DCs 2 weeks before promo, (d) negotiate vendor contribution to promotional cost per PUR-026 | Category Manager | VP Merchandising | 1–2 days/promo |
| 2 | Vendor adjusts VMI replenishment: (a) vendor pre-ships promotional stock to DCs, (b) VMI system temporarily overrides max stock level for promo period, (c) additional PO created for promo stock (separate from auto-replenishment), (d) promo stock received and staged for rapid deployment to stores | Vendor / VP Supply Chain | Category Manager | Pre-promo |
| 3 | Post-promo: (a) VP Supply Chain reconciles promo VMI stock: (i) promo qty sold vs. promo qty received, (ii) unsold promo stock: return to vendor or sell at regular price, (b) Category Manager reviews promo performance per VMI vendor, (c) VMI parameters reset to standard levels | VP Supply Chain / Category Manager | VP Merchandising | 2–3 days/post-promo |

### System Touchpoints
- VMI promotional parameter override (W1940.2)
- Promotional VMI stock tracking (W1940.3)
- Integration with W13 (promotions) and W57 (promo stock allocation)

### Pain Points / Risks
- **Promo stock excess**: If promo doesn't perform as expected, excess VMI stock sits in DC; vendor may not accept return; negotiate promo stock buyback clause


### Automation Opportunity
- System auto-identify of "identify VMI SKUs in upcoming promo per W13" (replaces manual Step 1).
- System auto-create of "created for promo stock" (replaces manual Step 2).
- System auto-review of "reviews promo performance per VMI vendor" (replaces manual Step 3).

### Controls
- CTL-377 (ensure controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2).)
- operational: Category Manager review and approval gate; operational: periodic reconciliation against source documents

### Time Estimate
- 1–2 days pre-promo planning; 2–3 days post-promo reconciliation

## W1941. VMI Vendor Performance & Compliance Review

| Field | Detail |
|---|---|
| **Trigger** | Quarterly VMI vendor review |
| **Frequency** | Quarterly |
| **Volume** | 12 VMI vendors reviewed |
| **Owner** | VP Supply Chain |
| **Participants** | VP Supply Chain, Category Manager, Vendor |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | VP Supply Chain compiles quarterly VMI scorecard per vendor: (a) fill rate: % of VMI SKUs at or above minimum stock level, (b) stockout rate: % of VMI SKUs at zero stock, (c) overstock rate: % of VMI SKUs above maximum stock level, (d) replenishment lead time: average days from stock signal to delivery, (e) ASN accuracy: % of receipts matching ASN within tolerance, (f) GR accuracy: % of deliveries with quantity discrepancies, (g) promo stock compliance: did vendor deliver promo stock on time and in full? | VP Supply Chain | VP Merchandising | 1 day/quarter |
| 2 | VP Supply Chain meets with each VMI vendor: (a) present scorecard results, (b) discuss improvement areas, (c) set targets for next quarter, (d) review VMI parameter adequacy: do min/max levels need adjustment?, (e) discuss new product introductions or phase-outs planned | VP Supply Chain | VP Merchandising | 1–2 hours/vendor/quarter |
| 3 | Annual: VP Supply Chain evaluates VMI program effectiveness: (a) compare VMI vendor performance to non-VMI vendor performance (fill rate, stockout, inventory turns), (b) calculate VMI program ROI: (reduced procurement labor + reduced stockouts) vs. (VMI system cost + vendor data sharing infrastructure), (c) recommend VMI program expansion or contraction | VP Supply Chain | VP Merchandising | 2–3 days/year |

### System Touchpoints
- VMI scorecard dashboard (W1941.1)
- Integration with W44 (vendor performance review) for consolidated scorecard

### Pain Points / Risks
- **Vendor complacency**: VMI vendors meeting minimum SLA may not strive for improvement; link VMI performance to overall vendor scorecard and business allocation decisions


### Automation Opportunity
- System auto-compile of "compiles quarterly VMI scorecard per vendor" (replaces manual Step 1).
- System auto-review of "review VMI parameter adequacy" (replaces manual Step 2).
- System auto-calculate of "calculate VMI program ROI" (replaces manual Step 3).

### Controls
- CTL-377 (ensure controlled execution — Vendor-Managed Inventory (VMI) Operations (PA-45.2).)
- operational: VP Supply Chain review and approval gate

### Time Estimate
- 1 day/quarter scorecard; 12–24 hours/quarter vendor meetings; 2–3 days/year program review
