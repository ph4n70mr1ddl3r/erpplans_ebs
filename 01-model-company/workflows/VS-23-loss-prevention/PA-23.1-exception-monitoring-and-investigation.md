## W837. Daily Store Exception-Based Reporting & Transaction Monitoring

| Field | Detail |
|---|---|
| **Trigger** | Automated — POS transaction data feed processed nightly; exception alerts generated when thresholds breached |
| **Frequency** | Daily (every store, every operating day) |
| **Volume** | 200 stores × ~15–25 flagged exceptions per store per day = ~3,000–5,000 exception alerts daily chain-wide |
| **Owner** | Loss Prevention Manager (Regional) |
| **Participants** | Store Manager, LP Analyst, POS System Administrator, Finance Controller, Senior LP Analytics Analyst |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Automated POS data extraction and exception rule engine execution — flag voids, no-sales, excessive discounts, high-value refunds, post-void patterns, and override frequency by cashier | LP Analyst, Senior LP Analytics Analyst | LP Manager (Regional) | 30 min (automated + validation) |
| 2 | Review prioritized exception dashboard — sort by severity (critical: repeat offenders, high-value anomalies; medium: single threshold breach; low: borderline) | LP Analyst | LP Manager (Regional) | 45 min |
| 3 | Cross-reference flagged transactions against CCTV timestamp log and cashier shift schedule | LP Analyst | Store Manager | 30 min |
| 4 | Escalate critical exceptions (value > PHP 10,000 or repeat pattern ≥ 3 occurrences) to regional LP Manager with evidence package | LP Analyst | LP Manager (Regional) | 15 min |
| 5 | Document non-critical exceptions in case log with disposition (explained, under review, escalated) | LP Analyst | Store Manager | 20 min |
| 6 | Generate daily LP summary report — total exceptions by category, store ranking, trend vs. prior week | LP Analyst | LP Manager (Regional) | 15 min |
| 7 | Store Manager reviews and acknowledges store-level exception summary; provides context for explained items | Store Manager | LP Manager (Regional) | 20 min |

### System Touchpoints
- **POS System** — transaction log extraction, void/refund/override audit trail
- **ERP LP Module** — exception rule engine, alert generation, case management
- **CCTV/DVR System** — timestamp cross-reference via API integration
- **BI Dashboard** — daily LP scorecard, store ranking, trend analysis
- **HR System** — cashier shift schedule, employee ID correlation

### Pain Points / Risks
- Exception rule thresholds may need frequent tuning to reduce false positives without missing genuine incidents
- Manual CCTV cross-referencing is time-intensive; AI-based video analytics not yet deployed
- Store Manager acknowledgment may be delayed during peak trading days
- Data latency between POS close and exception report availability (target: within 4 hours of store close)


### Automation Opportunity
- System auto-count of "discounts, high-value refunds, post-void patterns, and override frequency by…" (replaces manual Step 1).
- System auto-review of "Review prioritized exception dashboard — sort by severity" (replaces manual Step 2).
- System auto-log of "log and cashier shift schedule" (replaces manual Step 3).

### Controls
- CTL-225 (ensure shrinkage detection & case governance.)
- operational: Loss Prevention Manager (Regional) review and approval gate

### Staffing Implication
- 1 LP Analyst per 40 stores (5 regional LP Analysts chain-wide) + 1 National LP Analytics Lead
- Each analyst handles ~600–1,000 exceptions daily, requiring strong data analysis skills
- Store Managers allocate 20 min daily to exception acknowledgment

### Time Estimate
- Automated processing: 30 min
- Analyst review and disposition: ~2 hours per analyst per day
- Store Manager acknowledgment: 20 min per store per day
- **Total daily effort: ~13 analyst-hours + 200 × 20 min Store Manager time (67 hours) = 80 person-hours chain-wide**

## W839. Internal Theft Investigation & Employee Dishonesty Case Management

| Field | Detail |
|---|---|
| **Trigger** | Exception report pattern (W837), CCTV observation (W838), anonymous tip, or inventory variance threshold breach |
| **Frequency** | As-needed; estimated 5–10 active investigations ongoing at any time chain-wide |
| **Volume** | ~50–80 completed investigations per year; average case duration 2–6 weeks |
| **Owner** | LP Manager (Regional) |
| **Participants** | LP Investigator, HR Manager, Legal Counsel, Store Manager, Finance Controller, Union Representative (if applicable), Forensic / Fraud Investigator |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Receive and document allegation — source (exception report, tip, CCTV), subject employee(s), initial evidence summary, and estimated loss value | LP Investigator | LP Manager (Regional) | 1 hour |
| 2 | Conduct preliminary assessment — verify exception patterns, review transaction history (30-day lookback), cross-reference with inventory variance data | LP Investigator | LP Manager (Regional) | 4 hours |
| 3 | Determine investigation classification — minor (< PHP 50,000): store-level resolution; major (> PHP 50,000 or management-level subject): regional/national investigation | LP Manager (Regional) | National LP Director | 1 hour |
| 4 | Build evidence package — compile transaction logs, CCTV footage, inventory discrepancy reports, witness statements, and pattern analysis | LP Investigator | LP Manager (Regional) | 8–16 hours (over multiple days) |
| 5 | Conduct integrity interview (with HR witness present) — present evidence, obtain written statement, document admission or denial | LP Investigator | LP Manager (Regional) | 1–3 hours |
| 6 | Determine disciplinary action in consultation with HR and Legal — options range from written warning to termination, criminal complaint, or civil recovery | LP Manager (Regional) | National LP Director | 2 hours |
| 7 | Process recovery — deduct from final pay (within DOLE limits), file insurance claim if applicable, issue demand letter for civil recovery | LP Investigator | Finance Controller | 4 hours |
| 8 | Close case — update case management system, archive evidence per retention policy, generate lessons-learned summary, update exception rules if new pattern identified | LP Investigator | LP Manager (Regional) | 2 hours |

### System Touchpoints
- **ERP LP Module** — case management, evidence linking, workflow tracking
- **POS System** — transaction history extraction for subject employee
- **HR System** — employee record, disciplinary action logging, final pay processing
- **Finance Module** — recovery accounting, civil recovery tracking
- **CCTV System** — evidence extraction, time-locked footage archive
- **Inventory Module** — variance analysis for subject department/category

### Pain Points / Risks
- Integrity interview requires HR witness; scheduling delays can compromise investigation
- DOLE regulations limit salary deduction for recovery (max 1 week per month under Art. 113 LC)
- Criminal complaint process in Philippine courts is slow (6–18 months to resolution)
- Risk of wrongful termination claim if evidence is insufficient — requires Legal sign-off
- Unionized stores may have CBA provisions requiring union representative presence


### Automation Opportunity
- System auto-document of "document allegation — source" (replaces manual Step 1).
- System auto-review of "review transaction history" (replaces manual Step 2).
- System auto-log of "logs, CCTV footage, inventory discrepancy reports, witness statements, and…" (replaces manual Step 4).

### Controls
- CTL-225 (ensure shrinkage detection & case governance.)
- operational: LP Manager (Regional) review and approval gate

### Staffing Implication
- 1 LP Investigator per region (5 investigators national) + 1 National LP Director
- Legal Counsel: 0.5 FTE allocated to LP cases
- HR Manager involvement: ~4 hours per case

### Time Estimate
- Average case: 20–35 person-hours over 2–6 weeks
- **Annual estimate: 50–80 cases × 25 hours average = 1,250–2,000 person-hours/year**

| **Frequency** | As-needed; estimated 3–5 active ORC cases at any time |

| **Owner** | National LP Director |
| **Participants** | LP Manager (Regional), LP Investigator, Legal Counsel, External Law Enforcement (PNP), Store Managers (affected stores), Industry LP Association (ORCA) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|

| 2 | Activate ORC case file — create dedicated case, assign lead investigator, establish secure evidence repository restricted from store-level access | LP Investigator | National LP Director | 2 hours |
| 3 | Coordinate with affected Store Managers — provide awareness briefing (without compromising investigation), deploy targeted surveillance, assign plain-clothes LP during peak risk windows | LP Manager (Regional) | National LP Director | 4 hours |
| 4 | Liaise with external partners — share anonymized intelligence with industry LP association (ORCA), coordinate with PNP if criminal activity threshold met | National LP Director | COO | 2 hours |
| 5 | Execute coordinated surveillance operation — deploy LP resources across multiple stores simultaneously based on predicted target pattern | LP Investigator | National LP Director | 8–40 hours (operation duration) |
| 6 | Apprehension and turnover — coordinate with PNP for in-store apprehension, evidence documentation, blotter filing, and prosecution support | LP Investigator | National LP Director | 4–8 hours |
| 7 | Post-case review — update ORC intelligence database, brief all Store Managers on new MO, enhance preventive controls, close case file | National LP Director | COO | 4 hours |

### System Touchpoints
- **ERP LP Module** — ORC case management, cross-store incident aggregation, MO pattern matching
- **CCTV System** — multi-store footage retrieval and comparison
- **BI Analytics** — geographic heat map of incidents, temporal pattern analysis
- **External Intelligence Platform** — industry LP association data sharing (ORCA Philippines)
- **PNP Coordination System** — blotter, case referral, evidence chain-of-custody

### Pain Points / Risks
- ORC rings often target multiple retailers simultaneously; intelligence sharing with competitors is culturally sensitive
- PNP response time may be slow for non-violent retail theft; private security apprehension has legal limitations
- High-value power tools and construction materials are primary ORC targets — estimated 30% of total shrinkage
- Provincial stores have less LP coverage and are more vulnerable to ORC
- Risk of physical confrontation during apprehension — requires trained security personnel


### Automation Opportunity
- System auto-identify of "Identify ORC pattern — aggregate theft incidents across stores by…" (replaces manual Step 1).
- System auto-create of "create dedicated case, assign lead investigator, establish secure evidence…" (replaces manual Step 2).
- System auto-assign of "assign plain-clothes LP during peak risk windows" (replaces manual Step 3).

### Controls
- CTL-310 (ensure controlled execution — Exception Monitoring & Investigation (PA-23.1).)
- operational: National LP Director review and approval gate

### Staffing Implication
- National LP Director: 30% of time allocated to ORC
- LP Investigators: 1 dedicated to ORC at national level
- Regional LP Managers: ad-hoc coordination role during active cases

### Time Estimate
- Per case: 50–80 person-hours over 4–12 weeks
- **Annual estimate: 12 cases × 65 hours average = 780 person-hours/year**

## W841. Refund & Return Fraud Detection, Investigation & Prevention

| Field | Detail |
|---|---|
| **Trigger** | Exception report flags refund anomalies (W837), or cashier reports suspicious return behavior |
| **Frequency** | Daily monitoring; investigation initiated as needed |
| **Volume** | ~200–300 flagged return anomalies per week chain-wide; ~15–25 confirmed fraud cases per month |
| **Owner** | LP Analyst / LP Manager (Regional) |
| **Participants** | Store Manager, Cashier, Customer Service Supervisor, Finance Controller |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Automated return anomaly detection — flag: returns without receipt exceeding PHP 5,000, same customer returning ≥ 3 times in 7 days, returns of commonly stolen items (power tools, copper wire, adhesives), refunds to different payment method than original purchase | LP Analyst | LP Manager (Regional) | 30 min (automated) |
| 2 | Review flagged returns — verify against original transaction (if receipted), check CCTV for return counter activity, cross-reference customer loyalty ID or government ID captured at return | LP Analyst | Store Manager | 30 min per case |
| 3 | Classify fraud type — receipt fraud (forged/altered receipt), wardrobing (used item return), employee collusion, return-of-stolen-merchandise, or organized return fraud ring | LP Analyst | LP Manager (Regional) | 15 min per case |
| 4 | For confirmed fraud: block customer from future no-receipt returns, recover funds if possible, escalate to investigation if value > PHP 20,000 or ring pattern detected | LP Manager (Regional) | National LP Director | 1 hour |
| 5 | Update return policy rules engine — tighten return window or require manager approval for flagged categories/individuals | LP Analyst | LP Manager (Regional) | 30 min |
| 6 | Generate weekly return fraud summary — trend analysis, top stores, top categories, estimated loss, policy recommendation | LP Analyst | LP Manager (Regional) | 1 hour |

### System Touchpoints
- **POS System** — return transaction log, receipt lookup, customer ID capture
- **ERP LP Module** — fraud detection rules engine, case management, customer flag database
- **CCTV System** — return counter footage, customer identification
- **CRM/Loyalty System** — customer return history, loyalty ID lookup
- **BI Dashboard** — return analytics, fraud trend reporting

### Pain Points / Risks
- Philippine Consumer Act (RA 7394) protects legitimate return rights — policy must not violate consumer protections
- No-receipt returns are a necessary customer service concession but account for ~60% of return fraud
- Forged receipts are increasingly sophisticated — requires POS receipt verification barcode
- Customer confrontation during fraud denial can escalate to social media complaints or DTI filing


### Automation Opportunity

- System auto-review of "Review flagged returns — verify against original transaction" (replaces manual Step 2).
- System auto-classify of "Classify fraud type — receipt fraud" (replaces manual Step 3).

### Controls
- CTL-225 (ensure shrinkage detection & case governance.)
- operational: LP Analyst / LP Manager (Regional) review and approval gate

### Staffing Implication
- LP Analysts: return fraud review is part of daily exception workflow (~1 hour/day)
- Customer Service Supervisors: trained on fraud indicators and escalation procedure
- 1 FTE dedicated to return fraud analytics at national level

### Time Estimate
- Daily monitoring: 1 hour per analyst
- Weekly summary: 1 hour per analyst
- Investigation: 2–4 hours per confirmed case
- **Annual estimate: ~800 person-hours for detection + ~600 hours for investigation = 1,400 hours/year**

## W842. Cash Handling Exception Monitoring & Sweethearting Detection

| Field | Detail |
|---|---|
| **Trigger** | Automated — POS cash variance threshold breach, or sweethearting pattern detected by analytics |
| **Frequency** | Daily monitoring; investigation as needed |
| **Volume** | ~100–150 cash variance alerts per day chain-wide; ~5–10 sweethearting investigations per month |
| **Owner** | LP Analyst / Finance Controller |
| **Participants** | Store Manager, Cashier, HR Manager, LP Investigator |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Automated cash variance monitoring — flag: drawer shortage > PHP 500, drawer overage > PHP 200, repeated small shortages by same cashier (≥ 3 in 5 days), no-sale drawer opens > 5 per shift | LP Analyst | Finance Controller | 30 min (automated) |
| 2 | Sweethearting pattern detection — flag: cashier passes items without scanning, manual price entry below SRP, unauthorized discount application, cancellation of items after customer leaves with merchandise, scanning personal loyalty card for customer purchases | LP Analyst | LP Manager (Regional) | 45 min daily review |
| 3 | Cross-reference cash exceptions with CCTV at POS terminal — verify legitimate explanations (system error, customer dispute, training issue) vs. deliberate manipulation | LP Analyst | Store Manager | 30 min per escalated case |
| 4 | For confirmed sweethearting: compile evidence package, escalate to LP Investigator for integrity interview (per W839 process) | LP Investigator | LP Manager (Regional) | 4–8 hours per case |
| 5 | Cash handling coaching — for non-fraud variances, Store Manager conducts corrective coaching with cashier; document in HR file | Store Manager | LP Manager (Regional) | 30 min per session |
| 6 | Monthly cash variance trend report — store ranking, cashier ranking, trend vs. prior month, root cause analysis for top 10 variance stores | LP Analyst | Finance Controller | 2 hours |

### System Touchpoints
- **POS System** — cash drawer audit trail, transaction detail, void/no-sale logging
- **ERP LP Module** — cash variance tracking, sweethearting analytics, cashier scoring
- **CCTV System** — POS terminal camera feeds with transaction overlay
- **HR System** — disciplinary action tracking, coaching documentation
- **Finance Module** — daily cash reconciliation, variance accounting

### Pain Points / Risks
- Sweethearting is difficult to detect without POS-CCTV transaction overlay technology
- Cashier turnover is high (~30–40% annually in Philippine retail); training investment is lost
- Small cash variances may be dismissed as immaterial but can aggregate to significant losses
- Cultural reluctance to accuse employees of dishonesty without overwhelming evidence
- Cash handling policies must comply with DOLE regulations on salary deductions for shortages


### Automation Opportunity
- System auto-monitor of "monitoring — flag" (replaces manual Step 1).
- System auto-scan of "scanning, manual price entry below SRP, unauthorized discount application,…" (replaces manual Step 2).
- System auto-validate of "verify legitimate explanations" (replaces manual Step 3).

### Controls
- CTL-225 (ensure shrinkage detection & case governance.)
- operational: standard operating procedures; system-enforced validation rules

### Staffing Implication
- LP Analysts: cash monitoring is part of daily exception workflow
- Store Managers: cash coaching requires 30 min per session (estimated 10 sessions/month per store)
- Finance Controller: monthly review of chain-wide cash variance

### Time Estimate
- Daily monitoring: 45 min per analyst
- Monthly report: 2 hours per analyst
- Investigation: 4–8 hours per case (240–960 hours/year for the 60–120 cases per the Volume)
- **Annual estimate: ~1,200 person-hours for monitoring + ~800 hours for coaching and investigation**

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|

| 3 | Identify fraud indicators — short shipment, phantom items (invoiced but not delivered), substitution (lower-grade product), duplicate delivery, or collusion with receiving clerk | LP Investigator | LP Manager (Regional) | 2–4 hours per case |
| 4 | Conduct vendor fraud investigation — compile receiving records, interview receiving clerk, review CCTV of dock area, contact vendor for explanation | LP Investigator | LP Manager (Regional) | 8–16 hours per case |
| 5 | Vendor resolution — issue debit memo for shortage, require vendor corrective action plan, escalate to Procurement for vendor review/suspension if pattern confirmed | Procurement Specialist | Procurement Manager | 4 hours per case |

### System Touchpoints
- **WMS/Receiving Module** — PO vs. received quantity variance tracking
- **ERP LP Module** — dock audit checklist, vendor fraud case management
- **Procurement Module** — vendor performance scoring, debit memo processing
- **CCTV System** — dock area camera coverage, receiving activity footage
- **Weighbridge/Scale System** — weight verification for bulk materials

### Pain Points / Risks

- Receiving clerks in provincial stores may have personal relationships with delivery drivers
- Weight verification is impractical for small-item shipments; only viable for bulk materials (cement, steel, lumber)
- Scale calibration drift can cause false positives; quarterly calibration required
- Short-staffed stores may skip receiving verification during peak hours


### Automation Opportunity
- System auto-validate of "verify incoming shipment against PO and ASN" (replaces manual Step 1).
- System auto-review of "Review receiving variance data — flag vendors with > 2% quantity variance rate…" (replaces manual Step 2).
- System auto-identify of "Identify fraud indicators — short shipment, phantom items" (replaces manual Step 3).

### Controls
- CTL-310 (ensure controlled execution — Exception Monitoring & Investigation (PA-23.1).)
- operational: LP Manager (Regional) review and approval gate

### Staffing Implication
- LP Analysts: dock audits as part of weekly field visit schedule
- Receiving Clerks: trained on fraud indicators (refresher every 6 months)
- LP Investigator: 1 case at a time; ~5–10 cases/year

### Time Estimate
- Per dock audit: 60 min
- Per investigation: 15–25 hours
- **Annual estimate: ~10,400 dock audit hours (~800/month, mostly absorbed by store receiving staff) + ~150 investigation hours = ~10,550 person-hours/year**

- System auto-review of "review of LP incidents, cash variances, receiving variances, damage rates, and…" (replaces manual Step 3).

### Controls
- CTL-310 (ensure controlled execution — Exception Monitoring & Investigation (PA-23.1).)
- operational: National LP Director review and approval gate

### Staffing Implication
- National LP Director: 30% of time on shrinkage analysis and program management
- LP Analysts: 1 FTE dedicated to shrinkage analytics
- Store Managers: accountable for store shrinkage result (KPI component)

### Time Estimate

## W1475. Coupon & Promotional Discount Abuse Detection, Pattern Analysis & Prevention

| Field | Detail |
|---|---|
| **Trigger** | Weekly exception report showing anomalous discount activity; or cashier discount override spike; or loyalty program redemption anomaly |
| **Frequency** | Weekly pattern analysis; ~10–20 confirmed abuse cases/month chain-wide |
| **Volume** | ~33.6M annual POS transactions; ~6 promotional events/year (per W13) with coupon activity; estimated 0.1–0.3% discount abuse rate |
| **Owner** | LP Operations Manager |
| **Participants** | LP Analyst, Store Manager, Cashier, Department Supervisor, Marketing (coupon issuance), Loyalty Program Manager |

### Background

BuildRight Depot runs bi-monthly sale events per W13 and loyalty exclusive promotions that generate high coupon and discount activity across 200 stores and 600 POS terminals. Promotional discount abuse takes many forms: (a) cashiers applying employee or trade discounts to non-qualifying customers (sweethearting per W842), (b) customers using expired or photocopied coupons, (c) cashiers stacking multiple discount codes that should not be combinable, (d) loyalty members sharing account credentials to pool points for higher-tier discounts, (e) employees using their own loyalty account for customer purchases to accumulate personal points, and (f) repeat coupon use beyond stated limits. With promotional discounts representing 3–5% of revenue (~PHP 2–3B/year), even a 0.1% abuse rate costs BuildRight PHP 2–3M annually. This workflow focuses specifically on detecting, analyzing, and preventing coupon and promotional discount abuse patterns.

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | **Automated discount exception monitoring**: System continuously monitors POS transactions for discount anomalies: (a) **Employee discount misuse**: transactions with employee discount applied but customer is not verified employee; (b) **Trade discount abuse**: trade discount rate applied without trade account scan per W112; (c) **Coupon stacking**: multiple discount codes applied to single transaction exceeding authorized total discount %; (d) **Promo code reuse**: same coupon code scanned > stated usage limit per customer; (e) **Price override patterns**: cashier price overrides > 20% below SRP per W5B requiring manager authorization — frequency by cashier; (f) **Loyalty points manipulation**: loyalty account with points accumulation spike inconsistent with purchase pattern | System | LP Analyst | Automated |
| 2 | **Weekly pattern analysis**: LP Analyst reviews weekly discount exception report: (a) top 20 cashiers by discount exception rate (discounts applied ÷ total transactions); (b) top 20 stores by promotional discount variance (actual discount % vs. planned discount % per W13 campaign); (c) loyalty accounts with anomalous points activity (earning spikes, rapid redemption, account sharing indicators — multiple phone numbers, multiple store locations); (d) coupon code usage patterns — codes used beyond geographic or time restrictions; (e) LP Analyst categorizes exceptions: systemic (policy gap), individual (single cashier/customer), or organized (coordinated pattern) | LP Analyst | LP Operations Manager | 3 hours/week |
| 3 | **Individual case investigation**: For flagged exceptions: (a) LP Analyst pulls transaction detail: timestamp, store, terminal, cashier, items, discount type, customer (if loyalty/ trade); (b) review CCTV footage at POS terminal per W838 for visual confirmation (cashier behavior, customer interaction, coupon presentation); (c) interview Cashier and Department Supervisor: was the discount appropriate? was manager authorization obtained? (d) if confirmed abuse: (i) employee — disciplinary action per HR policy (verbal warning for first offense, written warning for second, termination for third), (ii) customer — flag loyalty account, restrict future coupon usage, (iii) coupon code — deactivate and notify Marketing | LP Analyst / Store Manager | LP Operations Manager | 1–2 hours/case |
| 4 | **Systemic prevention measures**: LP Analyst recommends preventive controls based on pattern analysis: (a) POS system configuration changes: (i) hard-code coupon exclusions (cannot stack with other discounts), (ii) enforce coupon usage limits per customer (tracked by loyalty account or phone number), (iii) require manager biometric authorization for discounts > 15%; (b) process changes: (i) daily coupon code rotation (codes change daily, texted to registered customers), (ii) trade discount requires trade account card scan (no manual entry), (iii) employee discount restricted to employee's own purchases only (verified by employee ID + biometric); (c) Marketing campaign design changes: (i) unique single-use coupon codes instead of generic codes, (ii) digital coupons delivered via app (not printable) to prevent photocopying | LP Analyst | LP Operations Manager | 4 hours/month |
| 5 | **Promotional event post-mortem**: After each bi-monthly sale event per W13: (a) LP Analyst compiles discount abuse report: total discount exceptions, confirmed abuse cases, financial impact (over-discount amount), policy violations by type; (b) LP Operations Manager reviews with Marketing and Store Operations: (i) were promotional terms clear and enforceable? (ii) did store staff understand discount rules? (iii) what system controls prevented abuse? (iv) what new abuse patterns emerged?; (c) incorporate lessons learned into next promotional event design per W13 | LP Analyst / LP Operations Manager | COO | 2 hours/event |

### System Touchpoints
- POS discount monitoring engine — real-time exception detection for discount anomalies (W1475.1)
- Discount exception report — weekly report by cashier, store, discount type, and pattern (W1475.2)
- CCTV integration per W838 — POS transaction linked to camera footage for visual investigation (W1475.3)
- POS system configuration — coupon rules, stacking restrictions, usage limits, manager authorization thresholds (W1475.4)
- Loyalty system — account activity monitoring, points anomaly detection, account sharing indicators (W1475.2)
- Integration with W842 (sweethearting), W838 (CCTV), W13 (promotions), W112 (trade pricing), W5B (POS transaction), W17 (loyalty)

### Pain Points / Risks
- **Customer service vs. control trade-off** — stricter discount controls (biometric authorization, unique codes) slow checkout and frustrate legitimate customers, especially during peak sale events

## W1476. Gift Card & Store Credit Fraud Detection, Balance Manipulation Investigation & Controls

| Field | Detail |
|---|---|
| **Trigger** | System alert for anomalous gift card/store credit activity; or customer complaint about unexpected balance; or LP investigation reveals gift card involvement in fraud scheme |
| **Frequency** | ~5–10 suspected fraud cases/month chain-wide; quarterly control review |
| **Volume** | ~PHP 20–30M in gift card/store credit outstanding at any time; ~5,000–10,000 gift card transactions/month |
| **Owner** | LP Operations Manager |
| **Participants** | LP Analyst, Store Manager, CSR, IT POS Administrator, Finance (store credit accounting), Customer |

### Background

BuildRight Depot issues gift cards and store credit (e.g., customer refund issued as store credit instead of cash per W12, referral rewards per W1472, promotional giveaways). While gift cards and store credit are important customer retention tools, they are also common fraud vectors in retail: (a) employees creating fake returns to issue store credit to their own accounts, (b) cashiers activating gift cards without collecting payment (passing the activated card to accomplices), (c) customers using stolen credit cards to purchase gift cards (converting stolen card funds to untraceable store credit), (d) manipulation of store credit balances through system exploits, and (e) social engineering — callers claiming to be customers requesting balance transfers. With ~PHP 20–30M in outstanding gift card and store credit balances, fraud directly erodes BuildRight's margin. This workflow manages detection, investigation, and prevention of gift card and store credit fraud.

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | **Automated fraud monitoring**: System monitors gift card and store credit transactions for fraud indicators: (a) **Velocity alerts**: single gift card loaded with > PHP 10,000 in a single transaction; multiple gift cards activated on same terminal within 1 hour; (b) **Return-credit pattern**: employee-associated loyalty accounts receiving disproportionate store credit from returns (indicator of fictitious return scheme); (c) **Balance anomaly**: gift card balance increasing without corresponding purchase transaction; store credit balance changed outside normal system processes; (d) **Geographic impossibility**: same gift card/store credit used at two different stores simultaneously or within an implausible travel time; (e) **Payment method risk**: gift cards purchased with credit cards subsequently reported as fraudulent (chargeback risk) | System | LP Analyst | Automated |
| 2 | **Case triage & investigation**: LP Analyst reviews each alert: (a) confirm anomaly is genuine (not system error or legitimate unusual transaction — e.g., a contractor legitimately purchasing PHP 50,000 in gift cards for project giveaways); (b) for confirmed suspicious activity: (i) pull complete transaction history for the gift card/store credit account, (ii) identify the CSR/cashier who processed the transaction, (iii) review CCTV footage per W838 for the transaction timestamp, (iv) cross-reference with other fraud indicators — is the same cashier or store appearing in multiple alerts? (c) categorize fraud type: employee fraud, external fraud (stolen cards), system exploit, social engineering | LP Analyst | LP Operations Manager | 1–2 hours/case |
| 3 | **Immediate containment**: (a) for active fraud in progress: IT POS Administrator freezes the affected gift card/store credit account to prevent further use; (b) for suspected employee involvement: Store Manager removes cashier from POS duties pending investigation per HR policy; (c) for suspected stolen credit card purchases: LP Analyst notifies payment gateway to flag the card; (d) for system exploit: IT applies emergency patch to close the vulnerability | IT POS Administrator / Store Manager / LP Analyst | LP Operations Manager | Per incident |
| 4 | **Investigation resolution & recovery**: (a) if fraud confirmed: (i) **Employee fraud**: HR disciplinary process — repayment of stolen amount or termination per W19.5 separation; report to LP database; (ii) **External fraud**: file police report for stolen credit card activity; block customer account; if identity discovered, pursue civil recovery; (iii) **System exploit**: IT fixes vulnerability; quantify financial impact; Finance writes off unrecoverable loss; (b) LP Analyst documents case with evidence, resolution, and financial impact in LP case management system | LP Analyst / HR / IT / Finance | LP Operations Manager | 2–4 hours/case |
| 5 | **Quarterly control review & system hardening**: (a) LP Operations Manager reviews all gift card/store credit fraud cases from prior quarter: patterns, root causes, financial impact; (b) recommend system controls: (i) gift card activation requires manager authorization for values > PHP 5,000, (ii) store credit issuance requires supervisor approval and customer ID verification, (iii) daily reconciliation of gift card liability account (total cards outstanding × balances) vs. GL per W86, (iv) two-person control for bulk gift card activation (promotional giveaways), (v) store credit refund timeout — 24-hour hold before store credit can be used (cooling period to detect fraudulent returns); (c) IT implements approved controls | LP Operations Manager / IT | COO | 4 hours/quarter |

### System Touchpoints
- Gift card/store credit monitoring engine — real-time fraud detection with velocity, balance, and geographic alerts (W1476.1)
- Transaction history module — complete gift card/store credit audit trail from issuance to redemption (W1476.2)
- Account freeze capability — IT can freeze suspected compromised accounts instantly (W1476.3)
- Gift card liability reconciliation — daily balance verification vs. GL (W1476.5)
- POS system controls — activation limits, manager authorization, cooling periods (W1476.5)
- Integration with W838 (CCTV), W842 (cash handling exceptions), W12 (returns/store credit), W17 (loyalty), W5B (POS transaction)

### Pain Points / Risks
- **Gift card as money laundering tool** — purchased with stolen credit cards and used to buy merchandise that is then resold; difficult to prevent without real-time card verification
- **Employee collusion** — store credit fraud requires collusion between cashier (fictitious return) and accomplice (redeeming store credit); dual-person controls help but add processing time
- **Customer experience impact** — 24-hour cooling period for store credit penalizes legitimate customers who want to use their refund immediately
- **Social engineering** — callers impersonating customers to request balance transfers are difficult to verify without strong authentication (knowledge-based authentication questions)


### Automation Opportunity
- System auto-count of "accounts receiving disproportionate store credit from returns" (replaces manual Step 1).
- System auto-review of "reviews each alert" (replaces manual Step 2).
- System auto-flag of "flag the card" (replaces manual Step 3).

### Controls
- CTL-310 (ensure controlled execution — Exception Monitoring & Investigation (PA-23.1).)
- operational: LP Operations Manager review and approval gate; operational: periodic reconciliation against source documents

### Staffing Implication
- **LP Analyst**: ~10–20 hours/month on case triage and investigation; absorbed
- **IT POS Administrator**: ~2 hours/month on containment and control implementation; absorbed
- **LP Operations Manager**: ~4 hours/quarter on control review; absorbed
- **No incremental headcount**

### Time Estimate
- Weekly monitoring: automated
- Individual investigation: 1–4 hours/case × ~10 cases/month = ~20 hours/month
- Quarterly control review: 4 hours
- **Annual estimate: ~260–300 hours**

## W1542. Organized Retail Crime (ORC) Pattern Detection, Multi-Store Correlation & Law Enforcement Coordination

| Field | Detail |
|---|---|
| **Trigger** | Exception-based reporting (EBR) system identifies pattern of related theft incidents across multiple stores; or LP Officer reports suspected organized ring |
| **Frequency** | ~5–10 suspected ORC investigations/year; ongoing monitoring |
| **Volume** | Each investigation may involve 3–10 stores and PHP 500K–5M in losses |
| **Owner** | LP Director |
| **Participants** | LP Director, Regional LP Officers, Store Managers, IT Security, Legal Counsel, Philippine National Police (PNP) |

### Background

Organized Retail Crime (ORC) involves coordinated theft by professional groups targeting specific high-value categories — power tools, copper wire, branded adhesives, and high-end fixtures at BuildRight. Unlike opportunistic shoplifting, ORC rings operate across multiple stores and regions, use sophisticated methods (receipt fraud, barcode swapping, distraction teams), and resell stolen goods through informal markets or online platforms. Detecting ORC requires correlating incidents across stores and time periods, which is impossible with single-store analysis. This workflow governs the specialized process of ORC detection, investigation, and law enforcement coordination.

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | **Pattern detection**: System analyzes loss patterns across all 200 stores — (a) same SKU category with unusual shrinkage spikes at ≥ 3 stores within 30 days, (b) same vehicle/license plate at multiple store loading zones, (c) similar suspicious transaction patterns (excessive returns without receipt, repeated high-value voids by same cashier), (d) CCTV correlation of same individuals at multiple stores; generates ORC alert with supporting data | System / Regional LP Officer | LP Director | Automated + 2 hours/review |
| 2 | **Investigation activation**: LP Director reviews ORC alert; classifies investigation priority — High (losses > PHP 1M or suspected internal collusion), Medium (PHP 200K–1M), Low (< PHP 200K); assigns lead investigator; creates confidential investigation file restricted from store-level access | LP Director | VP Legal | 1 hour |
| 3 | **Multi-store evidence gathering**: Regional LP Officers at affected stores pull CCTV footage, transaction logs, exception reports, and inventory variance data; IT Security extracts digital evidence (access logs, transaction timestamps, POS override records); all evidence consolidated in secure investigation file | Regional LP Officers / IT Security | LP Director | 8–16 hours |
| 4 | **Suspect identification & surveillance**: For High-priority investigations, LP Director authorizes enhanced surveillance at targeted stores — additional CCTV monitoring, undercover LP presence, vehicle tracking (if warranted and legally permissible); coordinates with store management to maintain normal operations during surveillance | LP Director | VP Legal | 1–2 weeks |
| 5 | **Law enforcement coordination**: For confirmed ORC cases with sufficient evidence, LP Director coordinates with PNP Criminal Investigation Division — submits formal complaint with evidence dossier (CCTV footage, transaction records, inventory reports); Legal Counsel reviews to ensure BuildRight's reporting obligations are met and employee rights are protected | LP Director / Legal Counsel | VP Legal | 8–16 hours |
| 6 | **Internal collusion investigation** (if applicable): If evidence suggests employee involvement (e.g., cashier processing fraudulent voids, receiving clerk facilitating theft), LP Director coordinates with HR for employee investigation per W79 (grievance process); ensures due process while maintaining investigation integrity; employee suspension pending investigation per DOLE requirements | LP Director / HR Head | VP Legal | 1–2 weeks |
| 7 | **Case closure & prevention measures**: Upon case resolution (arrest, recovery, or closure), LP Director documents lessons learned; implements targeted prevention measures — enhanced CCTV angles at affected areas, POS procedure changes, vendor collaboration for product tagging; updates ORC pattern library in EBR system for future detection improvement | LP Director | VP Legal | 4 hours/case |

### System Touchpoints
- Multi-store pattern detection engine with cross-correlation algorithms (W1542.1)
- Secure investigation file management with role-based access restriction (W1542.2–3)
- CCTV timestamp correlation with POS transaction logs (W1542.3)
- EBR system ORC pattern library for continuous learning (W1542.7)

### Pain Points / Risks
- **Evidence admissibility**: Philippine courts have strict rules on evidence chain of custody; CCTV footage must be properly timestamped, stored, and documented to be admissible
- **Employee safety**: ORC rings may threaten or intimidate store employees who cooperate with investigations; LP must ensure employee safety protocols are in place
- **Cross-jurisdiction complexity**: ORC rings operating across Philippine regions (Luzon, Visayas, Mindanao) require coordination with multiple PNP regional commands


### Automation Opportunity
- System auto-generate of "generates ORC alert with supporting data" (replaces manual Step 1).
- System auto-review of "reviews ORC alert" (replaces manual Step 2).
- System auto-log of "logs, exception reports, and inventory variance data" (replaces manual Step 3).

### Controls
- CTL-310 (ensure controlled execution — Exception Monitoring & Investigation (PA-23.1).)
- operational: LP Director review and approval gate

### Time Estimate
- Pattern detection review: 2 hours/alert × ~20 alerts/year = 40 hours
- Investigation: 20–40 hours per investigation × ~8 cases/year = 160–320 hours
- Law enforcement coordination: 8–16 hours per case
- Prevention measures: 4 hours per case
- **Total: ~300–520 hours/year** (pattern review 40 + investigations 160–320 + law-enforcement 64–128 + prevention 32)
