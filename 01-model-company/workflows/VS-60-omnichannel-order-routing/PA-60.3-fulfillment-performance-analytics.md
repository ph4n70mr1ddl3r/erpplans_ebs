## W2302. Fulfillment KPI Dashboard

| Field | Detail |
|---|---|
| **Trigger** | Real-time; monthly deep dive |
| **Frequency** | Real-time + monthly |
| **Volume** | ~42,900 orders/month (per profile §8.5) |
| **Owner** | Ecommerce Operations Manager |
| **Participants** | Ecom Ops Manager, VP Marketing |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Dashboard: fill rate by source, SLA compliance, split rate, cost per order, satisfaction by fulfillment type, return rate by source; daily flag review + monthly root cause analysis | System / Ecom Ops Manager | VP Marketing | 2–3 hours/day + 4–6 hours/month |

### System Touchpoints
- Analytics/BI (links to VS-27 / W113, W231 QBR dashboard) — the fulfillment-KPI dashboard
- Order/inventory (links to VS-10 / W98, VS-05 / W105) — the source data
- Alerting (links to VS-27 / W380) — the daily-flag auto-alert

### Pain Points / Risks
- **Dashboard-overload risk**: too many KPIs dilute attention; mitigated by the daily-flag review (only anomalies) and the structured monthly deep-dive
- **Metric-gaming risk**: a source games a metric (e.g., marks "shipped" before actual ship to hit SLA); mitigated by the W2300 quality audit and the cross-metric consistency check

### Automation Opportunity
- Dashboard auto-refreshed; anomalies auto-flagged

### Controls
- CTL-411 (ensure controlled execution — Fulfillment Performance & Optimization Analytics (PA-60.3).)
- Operational: Ecom Ops Manager daily/monthly sign-off; VP Marketing escalation on chronic KPI-miss

### Time Estimate
~2.5 hours/day + ~5 hours/month = **~700 hours/year** Ecom Ops Manager.

| **Owner** | IT Data Science Lead |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Reviews: accuracy, SLA achievement, cost optimization; A/B tests alternatives; adjusts weightings (speed vs. cost vs. accuracy); adds new inputs; deploys after testing | Data Science Lead | CIO | 5–10 days + 3–5 days |

### System Touchpoints
- Routing algorithm (links to VS-60 / W2286, VS-128 / AI-ML governance) — the algorithm under optimization
- A/B testing (links to VS-30 / W398 PoC, VS-133 OpEx) — the test harness
- AI/ML governance (links to VS-128 / W689 AI model governance) — the model-change governance

### Pain Points / Risks
- **Algorithm-regression risk**: a tuning change degrades performance in production (the A/B test didn't catch a real-world condition); mitigated by the canary-release (5% traffic first) and the rollback readiness
- **Overfitting risk**: the algorithm overfits to a recent period's pattern and underperforms on the next; mitigated by the multi-period validation (not single-period tuning)

### Automation Opportunity
- A/B test auto-instrumented; canary-release auto-gated

### Controls
- CTL-411 (ensure controlled execution — Fulfillment Performance & Optimization Analytics (PA-60.3).)
- operational: AI/ML governance — links to VS-128; operational: CIO sign-off on algorithm changes

### Time Estimate
~7.5 days/quarter = **~300 hours/year** Data Science Lead.
