## W4801. BOPIS-to-Locker Staging, Compartment Assignment & Replenishment

| Field | Detail |
|---|---|
| **Trigger** | BOPIS order ready (VS-10); locker compartment available |
| **Frequency** | Per order (continuous) |
| **Volume** | ~BOPIS-to-locker orders scaling with adoption (subset of ~42,900 BOPIS orders/month per profile §8.5) |
| **Owner** | Locker Program Manager / Store Ops (VS-07) |
| **Participants** | Ecommerce/OMS (VS-10), Stock Associate (VS-07), Store Ops (VS-07) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | On BOPIS order ready (VS-10), route eligible orders to the locker channel (vs counter pickup): select the right compartment size from the order's item dimensions (W4796 mix), auto-assign an available compartment via the locker/OMS integration (W4807), and generate the pick task for the stock associate | OMS / Locker Platform / Stock Associate | Locker Program Manager | Per order |
| 2 | Pick & stage the order into the assigned compartment: scan items into the compartment, lock it, trigger the access-code/QR delivery to the customer (W4802) and the pickup-ready notification (W4805); manage the SLA (profile §8.2 BOPIS pick SLA 4 hrs) | Stock Associate / OMS | Store Manager | Per order |
| 3 | Replenish & rebalance compartments continuously: free compartments on pickup (W4805), re-assign overflow (W4804), and maintain availability for peak BOPIS windows; coordinate with the counter-pickup fallback when lockers are full | Store Ops / Locker Platform | Store Manager | Continuous |

### System Touchpoints
- OMS/BOPIS (VS-10); locker platform (W4807); inventory (VS-05); store ops (VS-07); notifications (VS-75)

### Pain Points / Risks
- **Compartment-mismatch risk**: Wrong-size compartment for the order → can't fit → fallback to counter; mitigated by dimension-based assignment
- **Replenishment-bottleneck risk**: Slow staging → missed pick SLA; mitigated by pick-task prioritization
- **Starvation risk**: Lockers full → BOPIS rerouted to counter → locker underutilized in perception; mitigated by overflow/reclaim (W4804)

### Automation Opportunity
- Dimension-to-compartment auto-assignment; pick-task auto-routing; pickup-ready auto-notify

### Controls
- CTL-723 (ensure controlled execution — Collection Operations, Replenishment & Access Management (PA-164.2).)
- CTL-723: compartment assigned by item dimensions; staging within BOPIS SLA; availability rebalanced

### Time Estimate
- ~per order 2–5 min staging; ~continuous replenishment absorbed

### Cross-references
- links to VS-10 (BOPIS/OMS), VS-05 (inventory), VS-07 (store ops), W4802 (access codes), W4804 (overflow), W4805 (pickup/notify), W4807 (integration)

| # | Activity | Role (R) | Role (A) | Duration |

| 2 | Authenticate the pickup: customer scans/taps/PINs at the locker, the locker validates against the platform, opens the compartment, and confirms pickup → updates the OMS/inventory (VS-10/VS-05) and triggers the fulfillment-complete event; manage multi-method fallback if the primary method fails | IT / Locker Platform / OMS | Locker Program Manager | Per event |

### Automation Opportunity

### Controls
- CTL-723 (ensure controlled execution — Collection Operations, Replenishment & Access Management (PA-164.2).)

## W4803. Returns Drop-Off via Locker & Reverse-Logistics Handoff

| Field | Detail |
|---|---|
| **Trigger** | Customer initiates a locker return (VS-32); return-eligible item |
| **Frequency** | Per return |
| **Volume** | ~1,500–3,000 locker returns/month at maturity (subset of returns volume VS-32) |
| **Owner** | Locker Program Manager / Returns (VS-32) |
| **Participants** | Returns/Reverse-Logistics (VS-32), Store Ops (VS-07), CX (VS-13) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | On a customer-initiated locker return (online/app per VS-32), validate return eligibility (item, condition, policy), assign a compartment, and generate the drop-off access credential (W4802) + return label/instructions; communicate the return window | Returns / OMS / Locker Platform | Locker Program Manager / Returns Lead | Per return |
| 2 | Customer drops the item into the compartment; the locker confirms drop-off → updates the return/OMS (VS-32), triggers refund/credit per policy, and creates the reverse-logistics pick task; manage the condition/contents verification when the item is retrieved | Returns / Stock Associate / OMS | Returns Lead | Per return |
| 3 | Retrieve the returned item from the locker, verify contents/condition (vs the claimed return), and hand off to reverse-logistics (VS-32) for restock/RTV/refurbish/disposal; manage mismatch/fraud (empty box, wrong item — links VS-125) | Stock Associate / Returns / LP | Returns Lead / LP | Per return |

- **Eligibility-error risk**: Non-returnable item accepted → policy/Consumer-Act issue; mitigated by eligibility validation

### Automation Opportunity

### Controls
- CTL-723 (ensure controlled execution — Collection Operations, Replenishment & Access Management (PA-164.2).)

### Time Estimate

### Cross-references

## W4804. Overflow Management, Abandonment & Compartment Reclaim

| Field | Detail |
|---|---|
| **Trigger** | Compartment hold-period expiry (profile §8.2 BOPIS hold 5 days); locker at capacity |
| **Frequency** | Per expiry + continuous capacity management |
| **Volume** | ~300–800 overflow/abandonment events/month at maturity (hold-expiry driven) |
| **Owner** | Locker Program Manager / Store Ops (VS-07) |
| **Participants** | Store Ops (VS-07), CX (VS-13), Returns (VS-32) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Monitor compartment occupancy and the hold-period countdown; send reminders to customers as the hold approaches expiry (profile §8.2 5-day hold → auto-cancel & refund after); manage capacity alerts when a locker bank nears full | Locker Platform / Store Ops / CX | Locker Program Manager / Store Manager | Continuous |
| 2 | On expiry, reclaim the compartment: remove the uncollected order, process the auto-cancel & refund per BOPIS policy (VS-10), and return the item to sellable stock or to the returns/disposition chain (VS-05.3/VS-32); free the compartment for new orders | Stock Associate / OMS / Returns | Store Manager | Per expiry |
| 3 | Manage overflow: when a bank is at capacity, route new BOPIS to the counter (VS-10) or an adjacent locker, manage 3P-parcel compartment priority (W4799), and tune compartment mix (W4795) to reduce future overflow; track abandonment rate as a KPI (W4815) | Locker Program / Store Ops / OMS | Locker Program Manager | Continuous |

### System Touchpoints
- Locker platform (W4807); OMS/BOPIS (VS-10); inventory/disposition (VS-05.3/VS-32); payment/refund (VS-80/VS-101); CX (VS-13); analytics (W4815)

### Pain Points / Risks
- **Stuck-compartment risk**: Abandoned items occupying compartments → capacity loss; mitigated by the hold-period reclaim
- **Refund-leakage risk**: Refunding abandoned items without recovering the stock; mitigated by reclaim-then-restock sequencing
- **Customer-disappointment risk**: Auto-cancel of a still-wanted order; mitigated by reminders before expiry

### Automation Opportunity
- Expiry-countdown auto-reminders; auto-reclaim on expiry; auto-cancel & refund; capacity-based routing

### Controls
- CTL-723 (ensure controlled execution — Collection Operations, Replenishment & Access Management (PA-164.2).)
- CTL-723: hold-period enforced; reminders before expiry; reclaim-then-refund/restock; abandonment rate tracked

### Time Estimate
- ~per expiry reclaim 2–5 min; ~continuous capacity monitoring absorbed

### Cross-references
- links to VS-10 (BOPIS/hold policy), VS-05.3/VS-32 (disposition/returns), VS-80/VS-101 (refund), VS-13 (CX/reminders), W4795/W4799 (capacity/priority), W4815 (abandonment KPI)

### Steps

|---|---|---|---|---|
