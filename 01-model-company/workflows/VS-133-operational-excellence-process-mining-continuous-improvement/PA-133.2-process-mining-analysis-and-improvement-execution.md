## W4057. Process Discovery & End-to-End Process Mapping

| Field | Detail |
|---|---|
| **Trigger** | New improvement project; unmapped process; annual architecture refresh |
| **Frequency** | Per project + on demand |
| **Volume** | Per targeted end-to-end process (e.g., P2P, O2C, store-replenishment, returns) |
| **Owner** | OpEx Process Lead (Green/Black Belt) |
| **Participants** | Process participants (frontline), process owner, OpEx CoE |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | OpEx conduct process discovery: interviews, observation (gemba walk at store/DC), and document the as-is end-to-end flow with handoffs, systems, cycle times, and pain points | OpEx Process Lead / Participants | OpEx Process Lead | Per project |
| 2 | OpEx author the SIPOC and current-state value-stream map (process, flow, inventory, info, time) against the architecture (W4050) | OpEx Process Lead | Process Owner | Per project |
| 3 | OpEx validate the map with participants and the owner, and baseline against KPIs (W4054) | OpEx Process Lead / Owner | Process Owner | Per project |

### System Touchpoints
- Process repository (links to W4050); process mining prep (W4058); KPI baseline (W4054)

### Pain Points / Risks
- **Myth-vs-reality risk**: Documented process differs from actual; mitigated by gemba observation and process mining triangulation (W4058)
- **Scope-creep risk**: Mapping expands beyond the problem; mitigated by SIPOC and project charter

### Automation Opportunity
- Process-map generation seeded by event-log discovery (W4058) to short-cut manual discovery

### Controls
- CTL-630 (ensure controlled execution — Process Mining, Process Analysis & Improvement Project Execution (PA-133.2).)
- CTL-630: as-is map validated by process owner before analysis

### Time Estimate
- 1–3 weeks per end-to-end process

### Cross-references
- links to W4050 (architecture), W4058 (mining), W4054 (KPIs)

## W4058. Process Mining & Task Mining from ERP/System Event Logs

| Field | Detail |
|---|---|
| **Trigger** | Improvement project; performance anomaly; periodic health check |
| **Frequency** | Per project + continuous monitoring for key processes |
| **Volume** | High-volume processes: POS (2.8M txn/mo links to VS-08), P2P (~9,500 invoices/mo links to VS-15), store replenishment (~5,000/mo links to VS-02), returns (links to VS-32), ecommerce orders (~42,900/mo links to VS-10) |
| **Owner** | OpEx Data Lead / BI (links to VS-28) |
| **Participants** | OpEx CoE, BI/Data Engineering (links to VS-28.2), IT (links to VS-27), process owners |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | OpEx/BI ingest event logs from ERP/POS/WMS/ecommerce and run process mining to discover the *actual* process (variants, frequencies, deviations from standard) and task mining for desktop-based work | OpEx Data Lead / BI | COO | Per project |
| 2 | OpEx quantify process friction: throughput, bottlenecks, rework loops, wait times, automation candidates, and compliance deviations (e.g., bypassed approvals) | OpEx Data Lead | Process Owner | Per project |
| 3 | OpEx publish the mined view, reconcile with the as-is map (W4057), and feed findings to the pipeline (W4052) and continuous monitoring dashboard (W4066) | OpEx Data Lead / BI | COO | Per project |

### System Touchpoints
- Process-mining/task-mining platform; ERP/POS/WMS event logs (links to VS-08/VS-15/VS-10/VS-04); BI (links to VS-28.2); audit deviation feed (links to VS-21)

### Pain Points / Risks
- **Garbage-in risk**: Incomplete/dirty event logs distort the picture; mitigated by data-quality governance (links to VS-28.2)
- **Surveillance risk**: Task mining perceived as employee monitoring; mitigated by clear purpose, aggregation, and HR/Labor-Relations alignment (links to VS-84)

### Automation Opportunity
- Continuous process-mining health monitoring with anomaly alerting; auto-identification of automation candidates

### Controls
- CTL-630 (ensure controlled execution — Process Mining, Process Analysis & Improvement Project Execution (PA-133.2).)
- CTL-630: task-mining scoped with HR/Labor Relations; aggregated/role-level reporting; data minimization

### Time Estimate
- 2–6 weeks per major process to stand up; continuous thereafter

### Cross-references
- links to VS-28.2 (data eng), VS-84 (labor relations), VS-21 (compliance deviations), VS-30.2 (RPA)

## W4059. Bottleneck, Root-Cause & Value-Stream Analysis

| Field | Detail |
|---|---|
| **Trigger** | Mined/mapped process with quantified friction |
| **Frequency** | Per project |
| **Volume** | Per improvement project |
| **Owner** | OpEx Process Lead (Black Belt) |
| **Participants** | Process participants, subject-matter experts, process owner |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | OpEx identify constraints/bottlenecks (theory-of-constraints) and quantify their impact on end-to-end cycle time and throughput | OpEx Process Lead / Participants | OpEx Process Lead | Per project |
| 2 | OpEx facilitate root-cause analysis (5-Why, fishbone, Pareto) on defects/rework/wait, validating with data from mining (W4058) | OpEx Process Lead / SMEs | Process Owner | Per project |
| 3 | OpEx document findings, the future-state hypothesis, and feed into re-design (W4060) and the business case (W4065) | OpEx Process Lead | Process Owner | Per project |

### System Touchpoints
- Process-mining data (W4058); KPI baseline (W4054); analytics (links to VS-28)

### Pain Points / Risks
- **Symptom-vs-cause risk**: Treating symptoms; mitigated by structured RCA and data validation
- **Assumption risk**: Conclusions without data; mitigated by mining/KPI evidence

### Automation Opportunity
- Bottleneck auto-detection from event logs; root-cause hypothesis templating

### Controls
- CTL-630 (ensure controlled execution — Process Mining, Process Analysis & Improvement Project Execution (PA-133.2).)
- CTL-630: RCA validated with data; findings peer-reviewed by Master Black Belt

### Time Estimate
- 1–2 weeks per project

### Cross-references
- links to W4058 (mining), W4060 (re-design), W4065 (benefit case)

## W4061. Improvement Pilot Design, Execution & Hypothesis Testing

| Field | Detail |
|---|---|
| **Trigger** | Future-state design ready |
| **Frequency** | Per project |
| **Volume** | Per improvement project (often a single store/DC/category pilot) |
| **Owner** | OpEx Process Lead |
| **Participants** | Pilot site leadership, participants, BI (links to VS-28), process owner |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | OpEx design the pilot: hypothesis, scope (store/DC/category), duration, success metrics vs baseline (W4054), control/compare plan, and rollback plan | OpEx Process Lead / BI | Process Owner | Per project |
| 2 | OpEx/leadership execute the pilot at the site, monitor daily, capture issues, and adjust within the pilot window | OpEx / Pilot Site | Process Owner | Per project |
| 3 | OpEx/BI evaluate results (statistical significance where volume allows), decide go/no-go/adjust for rollout (W4064), and document lessons (W4071) | OpEx / BI | Process Owner / Sponsor | Per project |

### System Touchpoints
- KPI monitoring (W4054/VS-28); pilot-site ERP/POS config; analytics (links to VS-28)

### Pain Points / Risks
- **False-positive risk**: Pilot succeeds due to Hawthorne effect, not the change; mitigated by control sites and sufficient duration
- **Scale-up risk**: Pilot works locally but not at scale; mitigated by representative pilot sites and rollout phasing (W4064)

### Automation Opportunity
- Automated A/B-style pilot measurement with significance testing

### Controls
- CTL-630 (ensure controlled execution — Process Mining, Process Analysis & Improvement Project Execution (PA-133.2).)
- CTL-630: go/no-go decision recorded with evidence; rollback plan pre-approved

### Time Estimate
- 2–8 weeks per pilot

### Cross-references
- links to W4054 (KPIs), W4064 (rollout), VS-28 (analytics)

## W4062. Process Automation & Digitization Opportunity Scoping

| Field | Detail |
|---|---|
| **Trigger** | Mining/analysis identifies manual/repetitive work; automation candidate |
| **Frequency** | Per opportunity + periodic portfolio review |
| **Volume** | Enterprise automation pipeline (RPA, IDP, workflow, integration) |
| **Owner** | OpEx Process Lead / Automation CoE (links to VS-30.2) |
| **Participants** | OpEx CoE, Automation CoE (VS-30.2), Enterprise Architecture (VS-113), IT (VS-27), Finance (VS-17.4) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | OpEx scope the automation opportunity: the manual steps, volume/effort, variability, systems/data involved, and the candidate technology (RPA, IDP/OCR, workflow, API integration) | OpEx / Automation CoE | Process Owner | Per opportunity |
| 2 | OpEx/Finance build the business case (effort saved, accuracy/revenue benefit, TCO links to VS-135, sustainability), and route build vs buy to innovation/EA (VS-30/VS-113) | OpEx / Finance / EA | COO / CIO | Per opportunity |
| 3 | OpEx hand off approved automations to the build pipeline (VS-30.2 RPA lifecycle / VS-113 integration), and track realized benefit (W4065) | OpEx / Automation CoE | COO | Per opportunity |

### System Touchpoints
- Process mining (W4058); RPA/automation platform (links to VS-30.2); EA/integration (links to VS-113); TBM/TCO (links to VS-135)

### Pain Points / Risks
- **Wrong-tool risk**: RPA where integration is better (brittle, costly); mitigated by EA review (VS-113) and "buy/integrate-first" principle
- **Benefit-overstate risk**: Automation that mimics a broken process; mitigated by re-design first (W4060)

### Automation Opportunity
- Opportunity scoring; automation-portfolio analytics (realized FTE/accuracy benefit)

### Controls
- CTL-630 (ensure controlled execution — Process Mining, Process Analysis & Improvement Project Execution (PA-133.2).)
- CTL-630: build/buy/integrate decision via EA; TCO and benefit verified by Finance

### Time Estimate
- 1–2 weeks scoping per opportunity

### Cross-references
- links to VS-30.2 (RPA/automation), VS-113 (EA/integration), VS-135 (TBM/TCO)

## W4063. Control Design & Re-Engineering for Risk Reduction

| Field | Detail |
|---|---|
| **Trigger** | Re-designed process; audit finding; control failure |
| **Frequency** | Per project + on audit finding |
| **Volume** | Per improvement/control change |
| **Owner** | OpEx Process Lead / Risk & Controls (links to VS-21) |
| **Participants** | OpEx, Internal Audit (VS-21), Risk (VS-21.2), Compliance (VS-22), process owner |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | OpEx design/re-engineer preventive and detective controls into the future-state process (system-enforced where possible), aligned to the internal-controls-matrix and risk register (VS-21.2) | OpEx / Risk & Controls | Process Owner / VP Legal & Compliance | Per project |
| 2 | OpEx/Audit validate the control design (does it mitigate the risk without excessive burden), and update the controls register (links to internal-controls-matrix) | OpEx / Internal Audit | Process Owner | Per project |
| 3 | OpEx embed the control into SOPs (W4060) and monitoring (W4066), and confirm post-rollout (W4092) | OpEx / Quality | Process Owner | Per project |

### System Touchpoints
- Internal controls matrix; risk register (links to VS-21.2); SOP library (VS-30.3); monitoring dashboard (W4066)

### Pain Points / Risks
- **Control-gap risk**: Re-design removes an existing control inadvertently; mitigated by control-mapping and audit validation
- **Over-control risk**: Controls that strangle efficiency; mitigated by risk-based design and continuous review

### Automation Opportunity
- System-enforced controls (workflow gates, segregation-of-duties); continuous control monitoring

### Controls
- CTL-162 (ensure improvement benefit realization.)
- CTL-630: control design reviewed by Internal Audit; changes registered and tested

### Time Estimate
- Per project; 3–10 days

### Cross-references
- links to VS-21 (audit), VS-21.2 (risk), VS-22 (compliance), internal-controls-matrix

## W4064. Improvement Rollout, Change Management & Sustainment

| Field | Detail |
|---|---|
| **Trigger** | Pilot go-decision (W4061) |
| **Frequency** | Per project |
| **Volume** | Per improvement project (often network-wide: 200 stores / 4 DCs) |
| **Owner** | OpEx Process Lead / OCM Lead (links to VS-134) |
| **Participants** | OCM (VS-134), process owners, store/DC leadership, training (VS-19.4), comms (VS-103.1) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | OpEx/OCM build the rollout plan (phasing across sites, training cascade, comms, hypercare) and engage OCM for the people side (links to VS-134) | OpEx / OCM | Process Owner / Sponsor | Per project |
| 2 | OpEx/leadership execute the phased rollout, monitor adoption and KPIs, and intervene where adoption lags (links to W4091/W4092) | OpEx / Site Leadership / OCM | Process Owner | Per project |
| 3 | OpEx hand over to the process owner for sustainment, lock in controls (W4063) and standard work (W4060), and transition monitoring to the control tower (W4066) | OpEx / Process Owner | Process Owner | Per project |

### System Touchpoints
- OCM platform (links to VS-134); training/LMS (VS-19.4); comms (VS-103.1); monitoring (W4066)

### Pain Points / Risks
- **Reversion risk**: Sites revert to old ways post-rollout; mitigated by sustainment controls and adoption monitoring (W4092)
- **Change-saturation risk**: Too many changes at once; mitigated by OCM portfolio/capacity view (VS-134)

### Automation Opportunity
- Rollout tracking across 200 sites; adoption-rate monitoring with site-level intervention triggers

### Controls
- CTL-630 (ensure controlled execution — Process Mining, Process Analysis & Improvement Project Execution (PA-133.2).)
- CTL-630: sustainment owner assigned; control-stage sign-off; benefit verified at +90 days (W4065)

### Time Estimate
- Weeks to months depending on scope (network rollout)

### Cross-references
- links to VS-134 (OCM), VS-19.4 (training), W4066 (monitoring), W4065 (benefit)
