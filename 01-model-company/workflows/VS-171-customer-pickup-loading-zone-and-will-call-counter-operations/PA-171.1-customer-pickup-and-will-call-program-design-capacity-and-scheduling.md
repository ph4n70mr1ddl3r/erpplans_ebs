## W4961. Customer Pickup, Will-Call & Loading-Zone Program Strategy & Operating Model

| Field | Detail |
|---|---|
| **Trigger** | Program launch; format evolution (VS-109); CX/throughput issue; expansion |
| **Frequency** | Annual + on launch |
| **Volume** | 1 program applied to 200 stores × ~bulky-pickup share of 2.8M monthly transactions |
| **Owner** | VP Store Operations / Customer Pickup & Loading-Zone Program Manager |
| **Participants** | Store Ops (VS-07), CX (VS-13), Ecommerce (VS-10), HSE (VS-24), Real Estate/Facilities (VS-20/VS-138), Self-Haul Rental (VS-162) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Set the customer-pickup/will-call/loading-zone strategy & operating model: the will-call counter standard, the loading-bay model (drive-through vs back-of-house staging vs curbside), the appointment/time-slot model, the forklift-in-customer-area safety model (links VS-147/VS-24), the staffing/role model (counter, spotter, forklift operator, loader), and the CX/throughput KPIs | Program Manager / Store Ops / CX / HSE | VP Store Operations / COO | Annual |
| 2 | Build the operating standards: per-store loading-bay/zone capacity, signage/wayfinding (W4964), the customer-identification/release protocol (W4962), the SLA (order ready, wait time, load time), the appointment cadence (W4963), and the integration with BOPIS/ecommerce (W4967) and self-haul rental (W4968) | Program Manager / Store Ops / CX / IT | VP Store Operations | Annual |
| 3 | Govern the program across 200 stores: store-comms rollout (VS-63), training (links VS-19.4/VS-124), performance review (W4981), and continuous improvement; integrate into store-opening (VS-37) and remodel (VS-109) standards | Program Manager / Store Ops / Training | VP Store Operations | Continuous |

### System Touchpoints
- Store-comms/task (VS-63); order management (VS-10/VS-16); WMS/staging (VS-04); HSE (VS-24); facilities (VS-138); analytics (VS-28)

### Pain Points / Risks
- **Inconsistency risk**: Each store running pickup/loading differently → CX/safety variance; mitigated by the standard + store-comms
- **Capacity-blindness risk**: No appointment/capacity model → loading-bay queues; mitigated by the appointment model (W4963)
- **Safety-model risk**: Forklift-in-customer-area without a clear protocol → injury (VS-147); mitigated by the HSE-aligned safety model

### Automation Opportunity
- Capacity modeling; appointment engine; CX/throughput dashboards; standard-publish via store-comms (VS-63)

### Controls
- CTL-743 (ensure controlled execution — Customer Pickup & Will-Call Program Design, Capacity & Scheduling (PA-171.1).)
- CTL-743: standard documented; capacity model; safety model HSE-aligned; KPIs tracked

### Time Estimate
- ~4–6 weeks annual strategy; ~quarterly review

### Cross-references
- links to VS-07 (store ops), VS-10 (BOPIS/ecommerce), VS-162 (self-haul), VS-147 (premises safety), VS-24 (HSE), VS-63 (store comms), VS-37/VS-109 (open/remodel); sets inputs for W4962–W4968

## W4962. Will-Call Counter Operations, Order Staging & Customer Identification/Release

| Field | Detail |
|---|---|
| **Trigger** | Customer arrival for pickup; order ready notification (W4966) |
| **Frequency** | Per pickup (continuous, 200 stores) |
| **Volume** | ~5–8% bulky-pickup share of ~2.8M monthly transactions across 200 stores (~140,000–220,000/month) |
| **Owner** | Will-Call Counter Supervisor / Store Ops (VS-07) |
| **Participants** | Will-Call Counter Staff, Store Ops (VS-07), CX (VS-13), LP (VS-23) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Identify the customer & verify the order: at the will-call counter, verify customer identity/order (ID + order number — links VS-91 privacy, prevent wrong-customer release), pull the staged order (W4965), and confirm the order/items/condition with the customer before release | Counter Staff | Counter Supervisor | Per pickup |
| 2 | Release & document: release the order to the customer, capture the pickup confirmation/signature, update the order status (links VS-10/VS-16 — complete the fulfillment), and hand off to loading (W4970) or carry-out (W4974) for bulky goods | Counter Staff / Loader | Counter Supervisor | Per pickup |
| 3 | Manage counter exceptions: missing/incomplete order, wrong item, damaged-at-stage, payment/balance due, or identity/ownership dispute; route to resolution (VS-32 returns, VS-13 CX, VS-23 LP) and document | Counter Staff / CX / LP | Counter Supervisor / Store Mgr | Per exception |

### System Touchpoints
- Order management (VS-10/VS-16); WMS/staging (VS-04); ID/identity (VS-91); POS/POS lookup (VS-08); returns (VS-32)

### Pain Points / Risks
- **Wrong-customer-release risk**: Order released to the wrong person → loss/fraud (VS-23); mitigated by ID/order verification
- **Missing-order risk**: Customer arrives but order not staged → CX failure; mitigated by readiness controls (W4965)
- **Counter-queue risk**: Counter bottleneck → wait/abandonment; mitigated by appointment/queue mgmt (W4963/W4966)

### Automation Opportunity
- Order/ID auto-verify; QR/order-number scan; status auto-update on release; counter-queue dashboard

### Controls
- CTL-743 (ensure controlled execution — Customer Pickup & Will-Call Program Design, Capacity & Scheduling (PA-171.1).)
- CTL-743: ID/order verified before release; release captured; exceptions routed; privacy-compliant (VS-91)

### Time Estimate
- ~3–7 min per pickup at counter (verify + release + handoff)

### Cross-references
- links to VS-10/VS-16 (order mgmt), VS-04 (staging), VS-91 (privacy), VS-08 (POS lookup), VS-32 (returns), VS-13 (CX), VS-23 (LP), W4965 (staging), W4970 (loading), W4974 (carry-out)

## W4963. Pickup Appointment, Time-Slot & Loading-Bay Capacity Management

| Field | Detail |
|---|---|
| **Trigger** | Customer books pickup; capacity planning; peak (weekend/season) |
| **Frequency** | Continuous (per booking) + capacity planning |
| **Volume** | ~15–30 appointments per store per day × 200 stores |
| **Owner** | Loading-Zone/Will-Call Supervisor / Store Ops |
| **Participants** | Store Ops (VS-07), Ecommerce (VS-10), CX (VS-13), Data (VS-28) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Offer & manage pickup appointments/time-slots: a time-slot booking model (online/phone/counter) tied to loading-bay capacity and staffing, smoothing arrivals across the day, and prioritizing bulky/contractor orders (links W1193 priority) | Store Ops / IT / CX | Supervisor | Continuous |
| 2 | Manage loading-bay capacity: track bay/door availability, staging-space utilization, forklift/loader staffing, and the appointment queue; flag over-capacity and offer alternatives (later slot, delivery VS-06/VS-143, self-haul VS-162) | Supervisor / Store Ops | Supervisor | Continuous |
| 3 | Plan for peaks: weekend/season/typhoon-recovery and promo peaks (VS-64/VS-69), surge staffing/staging, and communicate slot availability to ecommerce (VS-10) and the call center (VS-13.1) | Supervisor / Store Ops / CX | Store Mgr | Per peak |

### System Touchpoints
- Appointment/slot engine (VS-10/VS-63); order management (VS-10/VS-16); WMS/staging (VS-04); analytics (VS-28); store-comms (VS-63)

### Pain Points / Risks
- **Overbooking risk**: More appointments than bay/staff capacity → queue/waits; mitigated by capacity-tied slots
- **No-show risk**: Customer misses slot → wasted capacity + restocking (W4978); mitigated by reminders (W4966) and expiry policy
- **Peak-overload risk**: Peak crush exceeds capacity; mitigated by peak planning and alternatives

### Automation Opportunity
- Capacity-tied slot engine; overbooking prevention; no-show prediction; peak-surge staffing alerts

### Controls
- CTL-743 (ensure controlled execution — Customer Pickup & Will-Call Program Design, Capacity & Scheduling (PA-171.1).)
- CTL-743: slots tied to capacity; bay/staff tracked; peaks planned; alternatives offered

### Time Estimate
- ~capacity planning 30–60 min/day; ~per-booking automated

### Cross-references
- links to VS-10 (ecommerce/BOPIS), VS-63 (store comms), VS-04 (staging), VS-06/VS-143 (delivery alternatives), VS-162 (self-haul), VS-64/VS-69 (seasonal/disaster peaks), W4966 (reminders), W4978 (no-show), W1193 (priority)

## W4965. Order Readiness, Pre-Stage Pick & Bulk-Goods Staging Area Operations

| Field | Detail |
|---|---|
| **Trigger** | Order placed/ready-for-pickup (VS-10/VS-11); appointment (W4963) |
| **Frequency** | Per order (continuous) |
| **Volume** | ~20–40 bulky-pickup orders per store per day × 200 stores |
| **Owner** | Staging/Receiving Lead / Store Ops (VS-07) |
| **Participants** | Store Ops (VS-07), Receiving (VS-07.3), DC (VS-04), Inventory (VS-05), CX (VS-13) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Pick & pre-stage the order: on order readiness, pick the bulky items (lumber/tile/cement/appliance) from yard/sales-floor/backroom (links VS-07.3 receiving, VS-05 inventory), verify against the order, and stage in the designated staging area tagged to the customer/order/slot | Staging Lead / Stock Associates | Staging Lead | Per order |
| 2 | Verify readiness & condition: confirm completeness (no shorts), condition (no damage W4979), special-order correctness (VS-09/VS-11), and catch-weight/cut-to-length accuracy (VS-115); flag exceptions before customer arrival | Staging Lead / Inventory / CX | Staging Lead | Per order |
| 3 | Manage the staging area: staging-slot utilization, FIFO/expiry (no stale holds — links W4978), segregation of customer orders, and feed the readiness notification (W4966) and counter (W4962) | Staging Lead / Store Ops | Supervisor | Continuous |

### System Touchpoints
- WMS/staging (VS-04); inventory (VS-05); order management (VS-10/VS-16); special orders (VS-09/VS-11); calibration (VS-115); analytics (VS-28)

### Pain Points / Risks
- **Not-ready risk**: Customer arrives but order not staged → CX failure; mitigated by readiness SLA and notification (W4966)
- **Wrong/incomplete-order risk**: Wrong/short order staged → return/complaint (VS-32/VS-13); mitigated by pre-arrival verification
- **Staging-congestion risk**: Staging area overflows → lost/mixed orders; mitigated by slot mgmt and hold-expiry (W4978)

### Automation Opportunity
- Auto-pick task on order readiness; staging-slot allocation; completeness auto-verify; readiness auto-notify (W4966)

### Controls
- CTL-743 (ensure controlled execution — Customer Pickup & Will-Call Program Design, Capacity & Scheduling (PA-171.1).)
- CTL-743: order verified before staging; completeness/condition checked; staging-slot tracked; readiness SLA

### Time Estimate
- ~per-order pre-stage 10–30 min (bulky goods)

### Cross-references
- links to VS-07.3 (receiving), VS-05 (inventory), VS-04 (staging), VS-10/VS-16 (order), VS-09/VS-11 (special/B2B), VS-115 (catch-weight), W4962 (counter), W4966 (notification), W4978 (hold-expiry)

## W4968. Self-Haul Rental (VS-162) & Customer-Hired-Vehicle Pickup Coordination

| Field | Detail |
|---|---|
| **Trigger** | Customer rents self-haul vehicle (VS-162) or arrives in own/hired vehicle |
| **Frequency** | Continuous |
| **Volume** | ~800–1,200 self-haul rentals + customer-vehicle pickups per month × 200 stores |
| **Owner** | Loading-Zone Supervisor / Self-Haul Rental (VS-162) / Store Ops |
| **Participants** | Self-Haul Rental (VS-162), Store Ops (VS-07), CX (VS-13), HSE (VS-24) |

### Steps

| # | Activity | Role (R) | Role (A) | Duration |
|---|---|---|---|---|
| 1 | Coordinate the self-haul rental + pickup: when a customer rents a self-haul vehicle (VS-162) or hires transport, link the rental to the order, schedule pickup/loading around the rental window, and stage the order to match the vehicle capacity | Self-Haul Rental / Loading Supervisor / Store Ops | Supervisor | Per pickup |
| 2 | Verify vehicle suitability: confirm the customer's vehicle (rented/owned/hired) can safely carry the load (size/weight/load rating — e.g., lumber length, appliance weight, tile pallet), and offer alternatives (delivery VS-06/VS-143, larger rental VS-162) if not | Loading Supervisor / CX | Supervisor | Per pickup |
| 3 | Manage rental-return & handoff: coordinate loading (W4970) within the rental window, load securement (W4972), the customer departure, and the rental return (VS-162); handle delays/extensions (links VS-162) | Loading Supervisor / Self-Haul Rental | Supervisor | Per pickup |

### System Touchpoints
- Self-haul rental (VS-162); order mgmt (VS-10/VS-16); staging (VS-04); delivery alternatives (VS-06/VS-143); analytics (VS-28)

### Pain Points / Risks
- **Vehicle-mismatch risk**: Load too big/heavy for the vehicle → unsafe overload or failed pickup; mitigated by suitability check
- **Rental-window risk**: Loading delays exceed rental time → extension charges/customer friction; mitigated by scheduling around the window
- **Coordination-failure risk**: Rental and order not linked → customer stranded; mitigated by the rental-order link

### Automation Opportunity
- Rental-order link; vehicle-suitability check from order dimensions; rental-window-aware scheduling

### Controls
- CTL-743 (ensure controlled execution — Customer Pickup & Will-Call Program Design, Capacity & Scheduling (PA-171.1).)
- CTL-743: rental linked to order; vehicle suitability verified; load securement checked (W4972); rental window managed

### Time Estimate
- ~per-pickup coordination 5–15 min

### Cross-references
- links to VS-162 (self-haul rental), VS-06/VS-143 (delivery alternatives), VS-10/VS-16 (order), VS-04 (staging), W4970 (loading), W4972 (securement)
